# AD 명령과 결과 예시

`192.0.2.10`, `lab.example`, `audit-user`, `<비밀번호>`는 예시입니다. 현재 작업에서 제공한 값으로 바꾸고 현재 작업 디렉터리 또는 지정된 `intent_dir`에서 실행합니다. 설치된 명령의 도움말이 최종 기준입니다.

## NetExec: 인증된 공유 조회

```bash
nxc smb 192.0.2.10 -d lab.example -u audit-user -p '<비밀번호>' \
  --shares > ./smb-shares.txt 2>&1
```

호스트의 서비스 정보, 인증 결과, 공유 이름과 접근 결과를 나누어 읽습니다. SMB 인증 성공만으로 관리자 권한이나 공유 읽기 성공을 주장하지 않습니다. 여러 대상의 출력은 성공·실패한 호스트를 구분해 전달합니다. 로컬 계정과 도메인 계정은 다른 주체이므로 `--local-auth`를 자동으로 추가하지 말고 계정 문맥에 맞춥니다. LDAP 등 다른 프로토콜의 옵션은 `nxc ldap --help`처럼 해당 도움말을 읽습니다.

## Impacket: LDAP 사용자 조회

```bash
impacket-GetADUsers -all -dc-ip 192.0.2.10 \
  'lab.example/audit-user:<비밀번호>' > ./ad-users.txt 2>&1
```

이 예시의 결과는 도메인 사용자 정보입니다. 특정 공격의 성공이나 암호 확보를 뜻하지 않습니다. Impacket 별칭에는 `.py`를 붙이지 않습니다. 다른 스크립트의 인증 인자가 같다고 가정하지 말고 각 `-h`를 확인합니다.

이미 제공된 Kerberos 캐시를 사용한다면 해당 명령의 `-k`·`-no-pass` 지원과 캐시 주체·SPN·DC 이름을 확인합니다. 캐시 경로는 `KRB5CCNAME`으로 전달할 수 있습니다. DNS 이름을 IP로 바꾸면 SPN 조건이 달라질 수 있으므로 IP 연결 성공만으로 Kerberos 설정이 맞다고 판단하지 않습니다.

## Certipy: AD CS 정보와 JSON 저장

```bash
certipy find -u 'audit-user@lab.example' -p '<비밀번호>' \
  -dc-ip 192.0.2.10 -json -output ./ad-cs
```

실제 생성된 JSON 파일명을 CLI 출력에서 읽습니다. `-output`은 출력 접두사이므로 입력값 자체가 최종 파일명이라고 가정하지 않습니다. 인증 기관·템플릿 식별자, 등록 권한을 가진 주체, 인증 조건을 함께 읽습니다. 표시된 취약 후보는 아직 해당 주체로 재현한 결과와 다릅니다. LDAP 조회는 성공했지만 CA의 일부 정보를 읽지 못했다면 확보한 정보와 누락 항목을 함께 남깁니다.

## 오류·부분 결과

| 현상 | 구분할 조건 |
| --- | --- |
| 이름 해석 실패·DC 연결 실패 | DNS·대상 주소·포트·라우팅 |
| Kerberos 시각·주체·SPN 오류 | 시계 차이, realm/도메인, 캐시 주체, 접속 이름 |
| 로그인 실패 | 실제 계정 도메인·인증 방식·계정 상태. 다른 호스트 실패와 합치지 않음 |
| 인증 성공 후 접근 거부 | 해당 객체/공유에 대한 권한. 인증 자체의 실패와 구분 |
| CA/템플릿 일부 조회만 성공 | 반환된 객체와 누락된 경로를 부분 결과로 기록 |
| 명령 또는 Python 모듈을 찾지 못함 | 설치·별칭 경로. 다른 도구의 가상 환경에 패키지를 섞지 않음 |

새 호스트·주체·서비스 등은 기존 자산 도구로, 관찰한 관계와 해석은 현재 작업의 사실 도구로 연결합니다. 원문에는 인증 정보가 포함될 수 있으므로 인계 요약에 비밀번호·티켓·인증서 내용을 복사하지 않고 필요한 파일 경로를 참조합니다.

공식 사용법: [NetExec](https://www.netexec.wiki/), [Impacket](https://github.com/fortra/impacket), [Certipy](https://github.com/ly4k/Certipy/wiki/05-%E2%80%90-Usage).
