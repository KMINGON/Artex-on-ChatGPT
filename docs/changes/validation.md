자동 회귀 검사와 실제 계정·브라우저 검증을 구분해 시점과 확인 범위를 기록합니다. 과거 버전의 검사 결과를 현재 변경 전체의 검사 결과로 합산하지 않습니다.

## 검증 범위

자동 회귀 검사는 모의 OpenAI SSE, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. 실제 API 키·ChatGPT 계정·운영 DB는 사용하지 않습니다. 계정별 프로그램 응답 확인은 자동 검사와 분리해 허용된 API 키·구독 계정의 짧은 연결 요청으로 진행합니다.

### 작업 템플릿 통합 검증

2026-10-23의 작업 템플릿 통합 후 루트 Go **19개 패키지**를 패키지별 빈 PostgreSQL DB에서 검사했고, 별도 Norma **14개 패키지**와 웹 **85개 테스트**·정적 빌드를 통과했습니다. 한국어·영어의 **3,167개 번역 키**도 일치합니다. 삭제한 정책 패키지는 현재 검사 대상에 포함하지 않습니다.

| 검사 | 확인한 내용 |
| --- | --- |
| 작업 생성 | 템플릿 저장 후 이름·분류·설명·목표·규칙·고급값을 수정하고 기존 작업 생성 API로 전달. 실제 DB의 작업·탐색 그래프·초기 의도·자산 규칙에 최종값 보존, 별도 정책 생성 없음 |
| 템플릿 편집 | 미지정·명시적 null·빈 문자열·0·false 구분, 30초·601초의 저장·적용, 시간 범위와 설명 길이 검증, 사용자 수정·삭제와 이름 충돌 보존 |
| 기존 데이터 | 이전 정책 원문 보존, 설명·기존 동작 제약으로의 원자적 이관, 실패 시 롤백, 재시작 시 중복 방지, 보관 작업 복원 후 이관 |

| 설정 화면 | 상단 자원 프리셋 버튼과 상세 설정 유지, 미저장 입력 보존, 저장 실패 후 재조회와 프리셋 적용의 경합 방지 |

실제 구독 계정의 `gpt-5.6-sol`·추론 강도 `medium`으로 **운영 · 관찰 템플릿의 Task 한 개**도 실행했습니다. JS·이미지·로그인·데이터 변경 버튼이 있는 로컬 실습 페이지에서 브라우저 화면과 HTTP 조회, 이미지 판독, 사용자 직접 인증 후 같은 세션 재개, 최종 보고서와 목표 완료를 확인했습니다. **6분 2초**, 모델 완료 응답 **43회 모두 Daybreak Blue**, 모델·도구 오류 **0건**, 업무 데이터 변경 **0건**이었습니다. 정상 로그인 POST 1건은 세션 생성에 사용했습니다. API 키는 사용하지 않았습니다.

별도 실제 런타임 검사에서는 HTTP·HTTPS 기록 프록시와 CA, Chromium 세션 격리·저장소 유지, 명령·Python 도구, api-recon의 SSE·WebSocket 수집을 확인했습니다. 실사용 중 발견한 인증 직후 화면 캡처 시간 초과는 폼 이동으로 재현했고 수정 후 즉시 캡처 100회와 미완료 웹폰트 캡처를 통과했습니다. 해당 화면 캡처 수정 후 전체 구독 Task를 다시 실행한 결과는 아닙니다. 템플릿의 빠른 재검색도 새 웹 빌드의 실제 Chromium에서 재검증했습니다.

이번 Task는 도구 연동과 지침 전달 검사입니다. 나머지 세 템플릿은 UI·저장·적용을 검사했으며 각 모드의 실제 장시간 침투 테스트, 모든 외부 MCP·알림 서비스, 실제 운영 사이트의 CAPTCHA를 검증한 것으로 보지 않습니다.

외부 전용 모델 설정이 필요한 `TestLiveContextReview` 한 건은 SKIP이며 일반 PostgreSQL 검사를 생략한 것으로 세지 않습니다. 자동 회귀 검사는 실계정을 호출하지 않았습니다.

### 브라우저·이미지·프리셋 검증

아래는 같은 날 **브라우저·이미지 기능을 처음 도입할 때 확인한 이력**입니다. 현재 작업 프리셋은 위의 기존 템플릿 경로를 사용하며, 당시의 별도 정책 주입·미리보기 검사는 현행 기능의 검증으로 세지 않습니다.

이 초기 검증에서는 **ChatGPT 구독만 실제 호출했고 API 키는 사용하지 않았습니다.** `gpt-6-sol`로 직접 이미지 입력, 텍스트·이미지가 섞인 함수 결과, 저장한 이력의 이미지 재전송을 확인했습니다. ARTEX 안에서는 브라우저 페이지 열기 → 사용자 인증 대기 → 같은 브라우저에서 로그인 → 제어 반환 → 스크린샷 시각 확인까지 완료했습니다. 연결 확인의 실제 응답 프로그램은 `daybreak_blue`였습니다.

2026-10-22 모델 설정 변경 후 루트 Go 전체 검사, 웹 **42개 테스트**(LLM 설정 **21개**), TypeScript 검사와 Docker 이미지 빌드·앱 정상 기동을 확인했습니다. 2026-10-23에는 실제 API 키의 모델 **139개**, 구독 계정의 표시용 모델 **8개**를 조회했습니다. API 응답에는 프로그램·추론 강도 정보가 없었고, 구독 응답의 프로그램·추론 강도·기본 추론 강도·정보 출처는 ARTEX 조회 결과에 보존되었습니다.

위 결과는 모두 `response.completed`까지 확인했습니다. Blue 명시 비교는 ARTEX를 거치지 않고 같은 공개 Responses 주소·요청 본문에 인증 방식만 바꾸어도 재현되었습니다. 해당 SIWC 응답의 차이가 프로그램 적용 자체인지 응답 메타데이터 문제인지는 공개 응답만으로 확정하지 않습니다. 이 API 키에서 Astra·6.1 Sol의 Blue 요청은 `unsupported_access_program`으로 거절되었습니다.

2026-10-23의 실제 Chromium 확인에서는 API 모델 조회·Blue/Standard 연결·저장·저장된 키 재조회, 구독 연결·설정 변경에 따른 이전 결과 해제를 확인했고 JavaScript 오류는 없었습니다. 이 실행은 이번 연결 필수·태그 중심 화면으로 변경하기 전 버전을 대상으로 했습니다. API·구독 GPT-6 Sol과 API `gpt-4o-mini`에서는 실제 어댑터의 함수 호출 → 도구 결과 전달 → 최종 답변까지 확인했습니다. 짧은 요청에 암호화 추론 항목은 생성되지 않아 해당 항목의 보존은 모의 회귀 검사 범위로 남습니다.

연결 필수·태그 중심 화면 변경에서는 웹 **57개 테스트**(LLM 설정 **36개**)와 정적 빌드를 통과했습니다. 연결 전 저장 차단, 설정 변경·재확인 실패·지연 응답 처리, 구독의 기존 Standard 보존, 실제 응답 프로그램의 표시·저장을 검사합니다. Go 패키지 검사도 통과했으며, 공유 DB 병렬 실행에서 잠금·임시 파일 정리 충돌이 발생한 DB·서버 패키지는 각각 빈 DB에서 분리 실행했습니다. 실제 PostgreSQL에서 연결 기록 저장·재조회·제거를 확인했고, 외부 전용 설정이 필요한 `TestLiveContextReview` 1건은 SKIP입니다. 이 변경에 대한 OpenAI 실계정 호출과 실제 브라우저 재검증은 별도로 수행하지 않았습니다.

루트 Go **19개 패키지**를 패키지별 빈 PostgreSQL DB에서 검사하고, Docker 소스 빌드와 [Compose 검사](../../scripts/test-compose.py)를 통과했습니다. 앱 초기화·관리자 로그인·한국어 기본값·인증 경계·재생성 후 데이터 보존을 확인했습니다. Noa 패키지와 해당 전용 검사는 제거했으며, 현재 엔진 검사에는 패키지 제외나 실패 허용 목록을 두지 않습니다.

Docker 네트워크 검증에서는 같은 네트워크의 서버 이름, `host.docker.internal`의 호스트 서버, 외부 HTTPS 접근을 확인했습니다. 별도 Docker 네트워크에서도 기본 공개 포트로 ARTEX에 접속했습니다. 실제 내부망의 다른 PC·사내 서버·VPN 경로는 각 실행 환경에서 확인해야 합니다.

실제 컨테이너의 공개 인증 메타데이터 조회·로그인 URL 생성·잘못된 state 거부·승인 취소 콜백을 확인했습니다. 성공 토큰 교환은 모의 서버로 검증했습니다. 별도의 실제 구독 계정 확인은 모델 목록과 짧은 추론 응답을 비교하는 범위이며, 다른 계정의 권한·실제 보안 작업 결과·Windows 네이티브 실행을 대신 검증하지 않습니다.

GitHub 워크플로는 제거했습니다. 로컬에서 루트 `go test ./...`, Norma 폴더의 `go test ./...`, 웹의 `npm test -- --run`·`npm run check:i18n`·`npm run build:static`, 문서의 `python3 scripts/check-doc-links.py`로 검사할 수 있습니다. DB 통합 검사는 테스트 전용 `ARTEX_PG_DSN`을 지정하고 패키지별 빈 DB로 분리해 실행합니다. Compose 검사는 로컬 이미지가 준비된 뒤 `python3 scripts/test-compose.py`로 실행하며, 자체 테스트 프로젝트·볼륨을 정리합니다.
