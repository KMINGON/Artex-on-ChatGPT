# 검증 범위와 방법

[변경점 전체 목록](../changes.md) · 비교 기준: 한국어판 ARTEX/global `fdfb7a1`

자동 회귀 검사, 실제 런타임 관측, 실계정 모델 판단 검사를 구분합니다. 이 문서는 현재 동작의 확인 범위와 한계를 설명하며 중간 버전의 검사 건수를 누적하지 않습니다. 과거 실행의 성공은 최신 소스 전체나 다른 계정·대상의 성공을 보장하지 않습니다.

## 검증 범위

자동 검사는 모의 OpenAI SSE·제공자, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. 실제 계정 요청은 자동 검사와 분리하며 허용된 계정·모델·횟수로 제한합니다. DB 의존 검사는 전용 DB에서 실행하고, 필수 설정 부재의 SKIP과 실패를 통과로 집계하지 않습니다.

현재 탐색·정보 인계 변경은 관련 Go·Norma 패키지와 격리 DB 통합·선택한 경합 검사로 확인했습니다. 웹을 포함한 Docker 이미지의 기동·건강 상태와 별도 Juice Shop 연결도 확인했습니다. 전체 루트 테스트나 장시간 진단을 다시 실행한 결과는 아닙니다.

| 가로채기 | 실제 DB 기본 규칙 → 가로채기 → Guard → 기록 경로. 파일의 명령 문자열과 실제 셸 명령, 대상 오류 본문과 실제 Guard 차단 집계 구분. 기본 도구 범위·명시적 MCP 선택·사용자 규칙 보존 |

지침 문자열·도구 계약 검사는 모델이 항상 같은 판단을 한다는 증명이 아닙니다. 자연어 작업의 모든 미완료 질문을 코드가 해석하거나 자동 실행하는 것으로 보지 않습니다.

### 그래프·상태·실행 검증

대표 통합 흐름은 **목표·의도 등록 → 마지막 목표의 조기 증명 거절 → Worker 결과 저장 → Planner 후속 판단 → 완료 → API의 작업·그래프 조회**입니다. 격리 DB와 실제 Engine·Planner·도구·API를 사용하며 모델 응답과 Worker 결과 도착을 고정해 완료 경합을 재현합니다. 별도 준비 실패·재개 검사에서는 실제 `runIntent`와 Worker를 모의 모델로 실행합니다. 실계정이나 외부 진단 대상을 호출하지 않습니다.

| 경로 | 확인한 내용 |
| --- | --- |
| 원자적 기록 | 사실 생산 의도, `yields`·부모·자산 앵커·범위의 동시 저장, 실패 시 전체 롤백 |
| 완료 판정 | `open`·`running`·`paused` 의도가 남은 마지막 증명 거절, 과거 완료 검토의 재검사, 늦은 사실·발견·Todo·같은 의도 재개 반영 |
| 중단·재개 | 사용자 pause, 직접 실행하는 목표 없는 작업, 시간 제한과 목표 달성 구분, 준비 실패·재시도의 현재 결과 인계 |
| 경합 | 선택한 Planner 인계·일시정지·구형 완료 상태 경로를 `-race`로 검사 |
| API·웹 | 가로채기 대상 스키마, 한국어·영어 키 일치, 변경 웹 파일의 Biome 오류 없음과 정적 빌드 |

그래프 페이지·작업 상태 표시·자동 브라우저 관찰의 별도 회귀 검사는 최신 페이지와 이웃 연결, 직접 연결한 작업의 읽기 경계, 부분 저장·취소·중복, 보관·복원, 늦은 UI 응답을 다룹니다. 이 영역의 전체 검사와 실제 Chromium 검증 이력은 2026-10-24~25 소스를 기준으로 하며 최신 변경 전체를 재검증한 것으로 합산하지 않습니다.

### 짧은 실제 모델 판단 검사

2026-10-26에 기존 ChatGPT 구독의 **`gpt-6-sol`·`medium`**으로 기본 Planner 지침·도구 스키마를 조립한 대표 합성 입력 세 건의 첫 판단을 확인했습니다. API 키를 사용하지 않았으며 작업 도구 handler 실행과 대상 서비스 요청은 모두 0건입니다.

| 사례 | 실제 첫 판단 |
| --- | --- |
| 대상 HTTP 500 `Blocked illegal activity`를 플랫폼 금지로 기록한 fact | 대상 응답의 출처를 구분하고 인증 후 주문 조회·객체 권한 대조를 근거 fact에 연결해 배정 |
| 수정 버튼이 없어 직접 API 검증을 금지로 기록한 fact | 허용된 임시 객체와 API로 정상 수정·교차 계정 권한 대조를 배정. UI 부재를 금지 조건으로 상속하지 않음 |
| 실제 DELETE 가로채기 차단을 생성·조회 금지로 확대 기록한 fact | 허용된 임시 자료 생성·조회를 배정하고 DELETE 차단은 유지. 미정리 객체와 사유를 인계하도록 안내 |

세 응답 모두 근거 fact를 보존한 후속 의도를 제안했고 조기 `prove_goal` 호출은 없었습니다. 이는 대표 사례의 첫 계획 판단에 대한 제한된 확인입니다. 최종 지침 전체의 모델 행동, 실제 Worker의 후속 검증·취약점 재현·장시간 탐색·제약 준수 전체나 원본 대비 발견량·시간당 성능 우위를 입증하지 않습니다. 동일 모델·추론 강도·템플릿·대상 초기 상태·실행 시간을 맞춘 원본/현재 A/B는 별도 검증 범위입니다.

| 이미지 | ChatGPT 구독의 직접 이미지 입력, 텍스트·이미지 함수 결과, 저장 이력의 이미지 재전송·스크린샷 판독 |
| 인증 | 로컬 페이지에서 사용자 직접 인증 후 같은 세션의 에이전트 재개. 종료·취소·늦은 응답은 별도 회귀 검사 |

허용된 구독 계정의 `gpt-5.6-sol`·`medium`과 운영 관찰 템플릿으로 로컬 실습 작업 한 개의 브라우저·이미지·사용자 인증·보고서·목표 완료도 확인했습니다. 이미지 경로의 실제 API 키 호출, 실제 사이트 CAPTCHA, 내부망·VPN별 접근, 모든 외부 MCP·알림, Windows 네이티브 실행은 확인하지 않았습니다.

### OpenAI 연결 관측

모의 SSE·HTTP 검사는 Responses 상태·도구 왕복, 옵션 생략, 프로그램 값·실제 응답 메타데이터, 스트림 무신호·keepalive·취소·한도·실패 사용량을 다룹니다. 연결 화면의 조회 순서·계정 변경·현재 입력으로 연결 필수·늦은 응답 폐기·명시 프로그램 보존은 웹 회귀 검사로 확인합니다.

실제 API 키·구독의 프로그램 응답과 모델 카탈로그 비교는 **2026-10-23의 해당 계정·시점**에 한정합니다. 구체적인 요청 차이와 확인일은 [OpenAI 호환성](openai.md#daybreak-선택)에 모아 두었습니다. 짧은 실제 호출에서 생성되지 않은 암호화 추론 항목의 보존은 모의 회귀 검사 범위입니다. 이전 실제 브라우저의 연결 성공을 최신 화면 전체의 실계정 검증으로 표현하지 않습니다.

## 로컬 검사 방법

변경 범위에 맞는 검사부터 실행합니다. 공통 실행·저장 경로를 전체 검증할 때는 루트와 별도 Norma 모듈을 각각 검사하며, 웹과 문서도 별도 확인합니다.

| 대상 | 명령·조건 |
| --- | --- |
| 루트 Go | `go test ./...`. DB 검사는 테스트 전용 `ARTEX_PG_DSN`을 지정하고 패키지별 빈 DB 사용 |
| Norma | `third_party/norma`에서 `go test ./...`. 루트 Go 검사에 자동 포함되지 않음 |
| 웹 | `web`에서 `npx vitest run`, 변경 파일 Biome 검사, `npm run check:i18n`, `npm run build:static` |
| 공개 문서 | `python3 scripts/check-doc-links.py`와 `git diff --check` |
| Compose | 로컬 이미지 준비 후 `python3 scripts/test-compose.py`. 자체 테스트 프로젝트·볼륨만 생성·정리 |

외부 전용 모델 설정이 필요한 `TestLiveContextReview`는 설정 없이 실행하면 SKIP입니다. 자동 검사에 실계정 자격증명을 넣지 않으며 실계정 요청·대상 진단은 해당 자동 검사와 별개로 기록합니다. GitHub 워크플로는 제공하지 않습니다.
