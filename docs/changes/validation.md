# 검증과 한계

[변경점 전체 목록](../changes.md) · 비교 기준: ARTEX/global `fdfb7a1`

원본과의 소스 비교, 오류를 재현하는 회귀 검사, 실제 브라우저 실행을 구분합니다. 검사 통과는 해당 실행·저장 계약을 확인한 결과이며, 실제 진단의 발견 수나 소요 시간 우위를 뜻하지 않습니다.

## 원본 비교 범위

Goals·Planner·Worker의 지침, 도구 연결과 호출 흐름, 그래프 저장·후속 계획·완료 조건을 원본과 대조합니다. 별도 Norma 모듈은 원본 v0.4.3과 비교합니다. 원본부터 존재한 지침·가로채기·스킬을 포크의 신규 제약이나 개선으로 분류하지 않습니다.

현재 탐색은 원본의 의도 배정과 목표 판단 경로를 사용합니다. Todo나 별도 완료 검토를 추가적인 완료 조건으로 요구하지 않으며, 브라우저 사용이나 별도 기본 템플릿의 검증 절차를 강제하지 않습니다. 이 정합성은 소스·도구 계약 검사 범위이며 자연어 지침에 대한 모델의 모든 행동을 증명하지는 않습니다.

## 회귀 검사 범위

| 영역 | 검사하는 실패와 보존 조건 |
| --- | --- |
| 도구 입력 | 선택값 생략·null·0, `params`/`parameters`, 잘못된 ID·타입, 잘린 도구 JSON의 실행 방지, 배치의 기존 부분 성공과 실제 trace 반환 ID |
| 그래프·증거 | 사실·의도·부모·자산 연결의 원자적 저장, 실패 롤백, 증거 연결·버전·최신 결과 조회 |
| 작업 상태 | 완료·일시정지·재개 경합, 준비·저장 실패, 늦은 Worker 결과, Planner 입력과 이벤트 보존 |
| 기본값 이관 | 정확한 배포 기본값만 변경, 사용자 편집·비활성화·삭제·기생성 작업 보존, 실패 롤백·재시작 중복 방지 |
| 자원 설정 | 수치만 저장하고 모델·인증·MCP·스킬·트래픽 설정 보존, 부분 저장 실패 시 롤백 |
| OpenAI | 모의 HTTP·SSE의 완료·미완료·오류·연결 중단, 원형 상태·이미지·사용량 보존, 출력 전 재시도와 출력 후 재실행 금지 |
| Norma | 요약 전 원문 보존, 전체 회차의 분할 요약, 실패·취소·비축약 결과 거절, 체크포인트 복구·Todo 재개·저장 오류 전파 |
| 가로채기 | 파일 내용과 실제 셸 실행 구분, 대상의 차단 응답과 ARTEX 훅 차단 구분, 사용자 규칙과 원본 판정 형식 호환 |
| 웹 | 설정 적용·늦은 응답·모델 변경·사용자 입력 보존, 한국어·영어 키와 정적 빌드 |

관련 검사는 모의 제공자, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. DB 검사의 설정 부재로 인한 SKIP은 통과로 집계하지 않습니다. 루트 Go 검사에 별도 모듈인 Norma 검사가 자동 포함되지 않으므로 각각 확인합니다.

빈 격리 PostgreSQL에서 루트 전체 Go 검사를 `go test -p 1 ./...`로 통과했습니다. 모의 OpenAI·구독 콜백, HTTP 작업 생명주기·템플릿 최종값 전달·일시정지와 재개·완료 저장 오류, 기본 지침 이관과 사용자 편집 보존을 포함하며 DB 검사 SKIP은 없었습니다. 실제 계정이 필요한 `TestLiveContextReview`는 실행하지 않았습니다. 기본 병렬 실행에서는 서로 다른 패키지의 DB 초기화와 활동 저장이 충돌할 수 있어 패키지를 순차 실행했습니다.

별도 Norma 모듈의 관련 검사, ScopeSentry의 실제 스킬 로딩·본문 전달, API 조사 스크립트의 문법과 문서 링크 검사도 통과했습니다. 웹의 관련 선별 검사·정적 빌드·Biome·한국어와 영어 번역 키 일치는 해당 웹 구현에서 확인한 범위이며, 지침 교정에는 웹 코드 변경이 없습니다. 실제 계정 호출이나 외부 진단 작업으로 탐색 성능을 검증한 결과는 아닙니다.

## 실제 브라우저 실행

격리된 컨테이너와 로컬 테스트 페이지에서 다음 경로를 확인했습니다. 운영 컨테이너·기존 계정·외부 사이트를 사용한 진단과 구분합니다.

| 경로 | 확인 내용 |
| --- | --- |
| 동시 실행 | 서로 다른 프로필 3개, JavaScript·폼·fetch 동작 |
| 사용자 조작 | 같은 페이지에서 수동 입력 후 MCP가 변경 상태 확인 |
| 재개 | 쿠키·localStorage·sessionStorage 보존, 재시작 후 세션 토큰 교체 |
| 이미지 | MCP 스크린샷, 페이지 전환 직후와 웹폰트 로딩 중 캡처 |
| 네트워크 | 신뢰하지 않는 인증서 거절, 명시적 CA 신뢰, 설정한 프록시를 거친 HTTPS |

이 검사는 Chromium 실행·세션·스크린샷·프록시 계약을 확인합니다. 실제 모델의 이미지 해석 능력, 모든 사이트의 인증 방식, CAPTCHA, 내부망·VPN·외부 MCP의 동작까지 검증한 것은 아닙니다.

## 재현 방법

변경한 영역의 관련 검사부터 선택합니다. 아래 명령은 검사 진입점이며 모든 명령을 매번 실행했다는 뜻은 아닙니다.

| 대상 | 방법 |
| --- | --- |
| Go | 관련 패키지에서 `go test`의 `-run`으로 회귀 검사를 선택. 전체 검사는 빈 전용 DB의 `ARTEX_PG_DSN`을 설정하고 `go test -p 1 ./...` 실행 |
| Norma | `third_party/norma`에서 `tool`·`harness`·`agentcore`·`transcript`·`compaction` 관련 검사 |
| 웹 | `web`에서 관련 `npx vitest run`, 변경 파일 Biome 검사, `npm run check:i18n`, `npm run build:static` |
| 문서 | `python3 scripts/check-doc-links.py`, `git diff --check` |
| 브라우저 | 이미지에 현재 스크립트를 연결해 `node scripts/browser-runtime.test.cjs` 실행 |
| Compose | 구성 확인과 전용 테스트 프로젝트의 기동·데이터 보존 검사. [검사 스크립트](../../scripts/test-compose.py) 참고 |

실계정 호출은 별도 범위로 진행하며 자격증명을 자동 검사 fixture나 로그에 넣지 않습니다. 일부 라이브 검사는 필요한 설정이 없으면 SKIP입니다. GitHub 워크플로는 제공하지 않습니다.

## 성능 비교의 한계

현재 코드에 대해 동일 조건의 원본·포크 장시간 진단 성능을 새로 측정하지 않았습니다. 모델·추론 강도·작업 설명·활성 도구·대상 초기 상태·시간 제한을 맞추고, 발견 수뿐 아니라 검증 근거·중복·실패·취약점 등록 지연을 함께 비교해야 합니다.

명확한 실행·저장 오류를 줄이는 수정과 모델의 탐색 전략은 구분합니다. 원문 보존·체크포인트 기록은 입력량이나 디스크 I/O를 늘릴 수 있고 브라우저 병렬 실행은 메모리·모델 사용량을 늘릴 수 있습니다. 오류 수정이나 원본과의 파이프라인 일치만으로 속도·깊이·최종 커버리지가 항상 더 높다고 보장하지 않습니다.
