# 검증과 한계

[변경점 전체 목록](../changes.md) · 비교 기준: ARTEX/global `fdfb7a1`

원본과의 소스 비교, 오류를 재현하는 회귀 검사, 실제 브라우저 실행을 구분합니다. 검사 통과는 해당 실행·저장 계약을 확인한 결과이며, 실제 진단의 발견 수나 소요 시간 우위를 뜻하지 않습니다.

## 원본 비교 범위

Goals·Planner·Worker의 지침, 도구 연결과 호출 흐름, 그래프 저장·후속 계획·완료 조건을 원본과 대조합니다. 별도 Norma 모듈은 원본 v0.4.3과 비교합니다. 원본부터 존재한 지침·가로채기·스킬을 포크의 신규 제약이나 개선으로 분류하지 않습니다.

현재 탐색은 원본의 의도 배정과 목표 판단 경로를 사용합니다. Todo나 별도 완료 검토를 추가적인 완료 조건으로 요구하지 않으며, 브라우저 사용이나 별도 기본 템플릿의 검증 절차를 강제하지 않습니다. 이 정합성은 소스·도구 계약 검사 범위이며 자연어 지침에 대한 모델의 모든 행동을 증명하지는 않습니다.

## 회귀 검사 범위

| 영역 | 검사하는 실패와 보존 조건 |
| --- | --- |
| 도구 입력 | 선택값 생략·null·0, `params`/`parameters`, 잘못된 ID·타입, 잘린 도구 JSON의 실행 방지, 배치의 기존 부분 성공과 실제 trace 반환 ID |
| 그래프·증거 | 사실·의도·부모·자산 연결의 원자적 저장, 실패 롤백, 증거 연결·버전·최신 결과 조회 |
| 작업 상태 | 완료·일시정지·재개 경합, 준비·저장 실패, 늦은 Worker 결과, Planner 입력과 이벤트 보존 |
| 기본값 이관 | 정확한 배포 기본값만 변경, 사용자 편집·비활성화·삭제·기생성 작업 보존, 실패 롤백·재시작 중복 방지 |
| 침투 테스트 도구 | CLI 설치·실행, 도구·스킬 기본 연결과 해제 보존, MCP 초기 OFF와 사용자 활성화 보존, 스킬 로딩 후 MCP 호출, 독립 Docker 네트워크·인증 연결 |
| 자원 설정 | 수치만 저장하고 모델·인증·MCP·스킬·트래픽 설정 보존, 부분 저장 실패 시 롤백 |
| OpenAI | 모의 HTTP·SSE의 완료·미완료·오류·연결 중단, 원형 상태·이미지·사용량 보존, 출력 전 재시도와 출력 후 재실행 금지 |
| Norma | 요약 전 원문 보존, 전체 회차의 분할 요약, 실패·취소·비축약 결과 거절, 체크포인트 복구·Todo 재개·저장 오류 전파 |
| 가로채기 | 파일 내용과 실제 셸 실행 구분, 대상의 차단 응답과 ARTEX 훅 차단 구분, 사용자 규칙과 원본 판정 형식 호환 |
| 웹 | 설정 적용·늦은 응답·모델 변경·사용자 입력 보존, 한국어·영어 키와 정적 빌드 |

관련 검사는 모의 제공자, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. DB 검사의 설정 부재로 인한 SKIP은 통과로 집계하지 않습니다. 루트 Go 검사에 별도 모듈인 Norma 검사가 자동 포함되지 않으므로 각각 확인합니다.

빈 격리 PostgreSQL에서 루트 전체 Go 검사를 `go test -count=1 -p 1 ./...`로 실행해 18개 패키지·테스트와 하위 테스트 2093개가 통과했습니다. 모의 OpenAI·구독 콜백, HTTP 작업 생명주기·템플릿 최종값 전달·일시정지와 재개·완료 저장 오류, 기본 지침 이관과 사용자 편집 보존을 포함하며 DB 검사 SKIP은 없었습니다. 실제 계정이 필요한 `TestLiveContextReview` 1개는 SKIP했습니다. 기본 병렬 실행에서는 서로 다른 패키지의 DB 초기화와 활동 저장이 충돌할 수 있어 패키지를 순차 실행했습니다.

별도 Norma와 웹 전체 검사는 이전 릴리스 준비 시 확인한 범위이며, 이번 MCP 배포 분리는 해당 모듈의 구현을 바꾸지 않았습니다. 이번에는 초기 MCP OFF·사용자 활성화 보존과 스킬 호출 경로를 격리 DB와 모의 HTTP로 검증하고, 서버별 준비 스크립트 17개·개발 환경 정리 스크립트 8개 회귀 검사를 통과했습니다. 웹 화면의 HTTP 헤더 입력·토글·수동 목록 새로 고침은 현재 코드와 문서를 대조했습니다. 실제 계정 호출이나 외부 진단으로 탐색 성능을 검증한 결과는 아닙니다.

격리 Compose에서 새 설치·정확한 버전·정적 UI·관리자 초기화·빈 ChatGPT 계정 상태와 연결 보호·컨테이너 재생성 후 자료 보존을 확인했습니다. 별도 `v0.1.0 → v0.1.1` 업그레이드에서는 기본 Planner·실습 목표·도구 설명의 이관, 사용자 편집·삭제·비활성·역할 연결·0/false·큰 정수·설정 보존, 기존 작업·그래프·관리자 비밀번호·JWT·인증 식별자·작업 파일 보존과 재시작 중복 방지를 확인했습니다. 이 검사는 운영 계정·운영 컨테이너를 사용하지 않았습니다.

서버별 `up`으로 격리 기동·health 대기·ScopeSentry 키 자동 발급과 인증을 확인했습니다. 실제 Docker 네트워크 자동 탐지도 확인했고, 호스트의 설정이 저장한 환경 파일을 덮어쓰거나 출력에 비밀값이 노출되지 않는지 검사했습니다. 같은 `up`을 재실행해 환경 파일·키·컨테이너 ID가 보존되는 것도 확인했습니다. MCP 서버별 독립 Compose를 격리 기동해 실제 ARTEX `mcphttp` 클라이언트로 ScopeSentry 도구 17개와 Metasploit 도구 16개를 조회했습니다. ScopeSentry 작업·템플릿·노드 목록과 Metasploit DB·세션·작업 상태의 읽기 조회, 서버 재생성 후 인증값과 저장 자료 보존을 확인했습니다. 문서의 Scanner 추가 네트워크 설정으로 외부 실습망에만 있는 HTTP fixture의 이름 해석·GET과 컨테이너 재생성 후 연결 유지를 확인했습니다. Metasploit은 명시적인 `false`로 검사했고 Host·Origin·Bearer 인증 회귀 9개도 통과했습니다. Scanner는 약 5분 후 `ksubdomain` 시작 검사가 타임아웃으로 실패한 뒤 온라인으로 등록됐고, `trufflehog` 초기화에는 `/apps/dictionaries: is a directory` 경고가 있었습니다. 이 메시지의 원인이 분리 구성인지 원본 이미지·설정인지까지 판정한 것은 아닙니다. 전체 플러그인 통과나 실제 대상 스캔·모듈 실행·LLM 도구 선택은 검증하지 않았습니다.

## 실제 브라우저 실행

격리된 컨테이너와 로컬 테스트 페이지에서 다음 경로를 확인했습니다. 운영 컨테이너·기존 계정·외부 사이트를 사용한 진단과 구분합니다.

| 경로 | 확인 내용 |
| --- | --- |
| 동시 실행 | 서로 다른 프로필 3개, JavaScript·폼·fetch 동작 |
| 사용자 조작 | 같은 페이지에서 수동 입력 후 MCP가 변경 상태 확인 |
| 재개 | 쿠키·localStorage·sessionStorage 보존, 재시작 후 세션 토큰 교체 |
| 이미지 | MCP 스크린샷, 페이지 전환 직후와 웹폰트 로딩 중 캡처 |
| 네트워크 | 신뢰하지 않는 인증서 거절, 명시적 CA 신뢰, 설정한 프록시를 거친 HTTPS |

이 검사는 Chromium 실행·세션·스크린샷·프록시 계약을 확인합니다. 실제 모델의 이미지 해석 능력, 모든 사이트의 인증 방식, CAPTCHA, 내부망·VPN·외부 MCP의 동작까지 검증한 것은 아닙니다.

## 빌드와 의존성 검사

`v0.2.1` 소스를 `ARTEX_BUILD_VERSION=0.2.1`로 Docker 빌드했습니다. 격리 Compose의 기동·표시 버전·정적 UI·관리자 초기화·인증 경계·컨테이너 재생성 후 데이터 보존 8개와 실제 API의 외부 MCP 초기 OFF·주소/인증 환경값을 넣은 뒤에도 OFF 유지 2개를 통과했습니다. Metasploit 준비 파일·예시·Compose 기본값은 `false`, 기존 명시적 `true`는 보존됨을 확인했습니다. 기존 사용자 설치의 전체 업그레이드와 실계정 호출은 이번에 수행하지 않았습니다.

이전 `v0.1.1` 준비에서 Compose의 소스 빌드와 호스트 빌드를 확인했으며, 당시 Docker 앱의 표시 버전은 `0.1.1`이었습니다. 두 바이너리의 빌드 정보에서 Go `1.26.10`, `golang.org/x/net v0.62.0`, `golang.org/x/crypto v0.58.0`, `github.com/klauspost/compress v1.18.7`을 확인했습니다. Go 모듈 체크섬과 `go vet ./...` 검사도 통과했습니다.

`govulncheck`의 2026-10-27 갱신 DB를 기준으로 루트 ARTEX와 별도 Norma에서 호출 가능한 취약점은 보고되지 않았습니다. 루트에는 사용하지 않는 `x/crypto/openpgp`의 모듈 경고 1건이 남으며 실제 import·호출은 없습니다. 정적 분석의 확인 범위이며 모든 취약점의 부재를 보장하지 않습니다.

웹의 `npm audit`와 `npm audit --omit=dev`는 각각 21건(치명적 2·높음 13·중간 5·낮음 1)을 보고했습니다. Next 서버와 shadcn CLI의 전이 의존성 경고가 포함되지만, 제품은 Go가 정적 웹 파일을 제공하며 해당 Node 서버를 실행하거나 웹 `node_modules`를 최종 이미지에 복사하지 않습니다. 개발·빌드 환경의 의존성 경고는 남아 있어 보안 검사 전체 통과로 표현하지 않습니다. Dockerfile과 같은 고정 버전의 별도 Playwright·MCP 런타임 npm 트리에서는 취약 패키지가 보고되지 않았습니다. Chromium·OS 패키지와 번들 내부의 전체 보안 검사는 이 결과에 포함하지 않습니다.

## 재현 방법

변경한 영역의 관련 검사부터 선택합니다. 아래 명령은 검사 진입점이며 모든 명령을 매번 실행했다는 뜻은 아닙니다.

| 대상 | 방법 |
| --- | --- |
| Go | 관련 패키지에서 `go test`의 `-run`으로 회귀 검사를 선택. 전체 검사는 빈 전용 DB의 `ARTEX_PG_DSN`을 설정하고 `go test -p 1 ./...` 실행 |
| Norma | `third_party/norma`에서 `tool`·`harness`·`agentcore`·`transcript`·`compaction` 관련 검사 |
| 웹 | `web`에서 관련 `npx vitest run`, 변경 파일 Biome 검사, `npm run check:i18n`, `npm run build:static` |
| 문서 | `python3 scripts/check-doc-links.py`, `git diff --check` |
| 브라우저 | 이미지에 현재 스크립트를 연결해 `node scripts/browser-runtime.test.cjs` 실행 |
| Compose | 구성 확인과 전용 테스트 프로젝트의 기동·데이터 보존 검사. [기본 앱 검사](../../scripts/test-compose.py), [MCP 설정 검사](../../scripts/test-prepare-mcp.py), [개발 정리 검사](../../scripts/test-dev-lab.py) 참고 |

실계정 호출은 별도 범위로 진행하며 자격증명을 자동 검사 fixture나 로그에 넣지 않습니다. 일부 라이브 검사는 필요한 설정이 없으면 SKIP입니다. GitHub 워크플로는 제공하지 않습니다.

## 성능 비교의 한계

현재 코드에 대해 동일 조건의 원본·포크 장시간 진단 성능을 새로 측정하지 않았습니다. 모델·추론 강도·작업 설명·활성 도구·대상 초기 상태·시간 제한을 맞추고, 발견 수뿐 아니라 검증 근거·중복·실패·취약점 등록 지연을 함께 비교해야 합니다.

명확한 실행·저장 오류를 줄이는 수정과 모델의 탐색 전략은 구분합니다. 원문 보존·체크포인트 기록은 입력량이나 디스크 I/O를 늘릴 수 있고 브라우저 병렬 실행은 메모리·모델 사용량을 늘릴 수 있습니다. 오류 수정이나 원본과의 파이프라인 일치만으로 속도·깊이·최종 커버리지가 항상 더 높다고 보장하지 않습니다.
