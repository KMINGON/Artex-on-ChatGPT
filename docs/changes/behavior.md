# 동작·사용성 변경

[변경점 전체 목록](../changes.md) · 비교 기준: 한국어판 ARTEX/global `fdfb7a1`

모델 연결과 저장 순서, 프리셋 적용 방식, 언어와 작업 상태 표시를 정리합니다. 저장된 사용자 입력과 실제 실행 시점의 설정을 구분합니다.

| 변경 | 이전 동작 | 현재 동작 |

초기 포크의 별도 작업 정책 선택·시스템 프롬프트 주입 경로를 제거하고 원본의 작업 템플릿을 확장했습니다. 기존 작업 생성 UI와 작업 전달 경로를 유지하며 템플릿 적용 후 모든 값은 직접 편집할 수 있습니다. 시스템 설정도 일반·고급 탭 분리를 걷어내고 기존 상세 화면 상단에 버튼 3개를 두었습니다. 이는 포크에서 추가한 기능의 사용성 보완이며 원본 결함으로 분류하지 않습니다.

### 모델 설정 화면

ChatGPT 계정 연결 카드는 유지합니다. 로그인과 모델 설정은 각각 관리하며, **모델 설정 탭의 카드 목록 아래 중앙에 있는 `＋ 모델 설정 추가`**로 모델을 등록합니다. 순환 설정 버튼은 **모델 설정 / 재시도와 백오프** 탭 오른쪽에 있습니다.

```text
ChatGPT 계정 연결 → 모델 설정 추가 → 계정 선택 → 모델 조회 → 모델 선택
OpenAI API 키    → 모델 설정 추가 → 키 입력   → 모델 조회 → 모델 선택
                                                        ↓
                                        옵션 설정 → 연결 확인 성공 → 저장
```

조회 전에는 모델 조회 버튼을 표시하고, 조회가 끝나면 모델 선택 목록과 새로고침 버튼을 표시합니다. 기존 설정을 편집할 때는 저장된 모델을 먼저 보여 주며, API 키를 다시 입력하지 않아도 저장된 키로 조회할 수 있습니다. 조회·모델 선택만으로 추론을 실행하지 않습니다. 다른 계정·키로 바꾸면 이전 목록을 재사용하지 않습니다.

새 설정은 연결된 구독 계정이 하나면 해당 계정을 미리 선택하며 API 키 방식으로 바꿀 수 있습니다. 이름은 선택한 모델에 맞춰 자동 입력하고 직접 수정할 수 있습니다. 기본 화면에서는 모델·추론 강도를 설정하고 프록시·속도 제한·컨텍스트 수동 설정·API 프로그램 등은 **고급 설정**에서 엽니다. API의 모델 ID 직접 입력도 고급 설정에 남겨 두었습니다. 구독 모델 목록에는 계정 카탈로그에 따른 **Daybreak / Standard / 미확인** 태그를 표시하며 별도 프로그램 토글은 두지 않습니다.

API는 모델 선택 목록 아래의 **Daybreak 확인** 또는 일반 **연결 확인**으로 선택한 모델의 실제 적용 프로그램을 확인합니다. 두 버튼은 현재 설정으로 같은 연결 요청을 보내므로 한 번 성공하면 충분합니다. API 프로그램의 기본값은 필드 생략이며, 지원·권한이 있는 모델에서는 OpenAI가 Daybreak를 선택합니다. 고급 설정에서 프로그램을 직접 지정했다면 그 값을 유지합니다.

성공하면 버튼에 **`실제 모델명 · Daybreak Blue / Standard · 연결됨`** 형식으로 표시하고, 응답 시간·확인 시각도 남깁니다. **현재 설정으로 연결 확인에 성공해야 저장·저장 후 사용 버튼이 활성화**됩니다. 키·계정·모델·프록시·추론 강도·API 출력 상한·프로그램을 바꾸거나 재확인에 실패하면 성공 상태를 해제합니다. 변경 전 요청이 늦게 도착해도 새 설정의 결과로 표시하지 않습니다. 편집창을 다시 열었을 때도 저장하려면 연결을 다시 확인합니다.

저장한 모델 카드에서는 API·구독 모두 실제 응답으로 확인한 **Daybreak / Standard** 태그를 사용합니다. 확인 기록이 없는 기존 프로필과 프로그램 정보가 없는 응답은 **미확인**으로 구분합니다. 기록은 확인 당시의 모델·프로그램·시각을 보관하는 표시 정보이며, 앞으로의 접근 권한이나 모든 작업의 성공을 보장하지 않습니다. 저장과 기본 모델 적용은 구분하며, 첫 사용 가능한 프로필의 자동 활성화 안내도 실제 서버 동작에 맞췄습니다.

### 한국어화

화면의 고정 라벨에 더해 **ARTEX가 기본 제공하거나 실행 중 생성하는 중국어 안내**를 한국어로 바꿨습니다.

| 범위 | 반영 내용 | 유지한 동작 |
| --- | --- | --- |
| 에이전트 | 기본 시스템 프롬프트, 변수 설명·예시, 보고서·재검증 지침, 작업·마무리 안내 | 역할, 작업 순서, 권한 범위, 템플릿 변수와 도구 호출 조건 |
| 도구 | ARTEX 도구 설명·인자 안내·오류·결과, Norma 대화형 셸·백그라운드 작업 알림 | 도구 이름·인자 키·자료형·필수값·enum·기본 인자와 실행 로직 |
| 가로채기 | 명령 규칙 20개·자산 규칙 4개의 표시 문구, Judge 정책·판정 사유, 승인·차단 안내 | 정규식·도메인·우선순위·활성 상태·시간 제한. 새 한국어 판정과 기존 중국어 판정 형식을 함께 검증 |
| 실행 화면 | 트리거 제목·컨텍스트, 첨부·인용 안내, 상태·오류·로그, 보조 질문 지침 | 기존 상태값·기록 형식. 한국어 로그 오류 분류 및 이전 인용 토큰 호환 |
| 기본 스킬 | `api-recon`, `scopesentry` 문서·예시 | 명령·프로토콜·응답 매칭 패턴과 파일 구조 |

기존 DB에는 확인된 이전 기본값과 **정확히 일치하는 부분만** 적용합니다. 도구는 설명 필드별로 비교하고, 프롬프트는 본문 전체를 비교해 새 버전을 추가합니다. 사용자 편집·도구 연결·비활성화·삭제한 규칙은 보존하며, 앞서 실행되던 기본값 강제 갱신에도 사용자 편집 보호를 추가했습니다. 새 설치는 한국어 기본값으로 시작합니다.

직접 수정한 본문, 확인되지 않은 더 오래된 기본값, 과거 대화·감사 기록·프롬프트 이력, 대상 사이트 응답과 외부 도구 출력은 일괄 번역하지 않습니다. 기존 사용자 프롬프트에 중국어 답변 지시가 남아 있다면 직접 수정하거나 에이전트 설정의 기본값 복원을 사용하세요. 도구의 기본값 복원은 연결·활성 상태도 초기화하므로 필요한 설명만 편집할 수도 있습니다.

번역 후에도 작은 컨텍스트 창에서 보조 질문 요약이 동작하도록, 실제 조립된 요청의 길이를 확인해 요약 조각 크기를 조정합니다. 스키마·템플릿·판정 파서·기존 DB 갱신은 회귀 검사로 확인합니다.

## 작업 상태와 그래프 표시

| 화면·기록 | 현재 동작 |
| --- | --- |
| 탐색 그래프 | 최신 노드와 연결된 이웃을 먼저 표시. 현재 표시 수/전체 노드·연결 수를 보여 주고 이전 기록을 더 불러올 수 있음 |
| 관련 작업의 그래프 | 직접 연결한 작업만 조회하고 그 작업의 진행 중 의도는 제외. 출처 작업 ID·읽기 전용 표시 유지 |
| 그래프 새로고침 | 이미 펼친 페이지 범위를 다시 조회해 삭제·재개 상태를 갱신. 다른 작업으로 이동한 뒤 도착한 응답은 적용하지 않음 |
| 자산 관찰 범위 | 시작점·기각된 항목을 제외한 fact/finding 연결 자산의 비율. 취약점 유형별 검증 완료율과 구분 |
| 작업 실행 시간 | 제한 없는 작업도 최초 실제 실행 시각을 저장. 이 값이 있는 작업은 생성 후 대기 시간을 실행 시간에서 제외하며, 옛 작업은 생성 시각 기준을 유지 |
| 웹·도구 상태 | 작업 목록과 `list_tasks`가 같은 계산을 사용해 대기열·일시정지·모델 체인 소진 상태를 일치시킴 |
| 현재 실행 설정 | 생성 시 저장된 Worker 수와 현재 전역 브라우저 상한을 구분. 역할별 요청 모델·추론·프로그램, 브라우저 MCP의 직접 접근 설정, 트래픽 캡처 표시 |
| 현재 Worker 진행 | 실행 중인 의도의 단계·도구 이름·마지막 실행 신호 경과를 5초마다 갱신. 메모리 관측값이며 결과 완료 판정이나 재시작 후 기록은 아님 |

탐색 그래프 API의 `nodes`·`edges` 형식은 유지하고 `total_nodes`·`total_edges`·`page_nodes`·`next_before`·`has_more`를 추가했습니다. `before` 커서와 `limit`으로 과거 기록을 조회하며 기본·최대 페이지 크기는 2,000개, 웹은 500개씩 확장합니다. 페이지에 닿는 연결의 반대편 노드도 반환하므로 화면에 한쪽 끝이 없는 선을 만들지 않습니다. 연결 이웃은 페이지 크기보다 많을 수 있습니다. [`db/exploration_graph_page.go`](../../db/exploration_graph_page.go), [`server/server.go`](../../server/server.go)의 `explorationGraph`가 이 경로입니다.

현재 실행 설정은 조회 시점의 값입니다. 표시된 모델·프로그램은 요청 설정이며 실제 응답값과 구분합니다. MCP 활성화와 Worker 직접 접근 허용도 Chromium 준비 완료나 페이지 접속 성공을 뜻하지 않으므로 실제 동작은 실행 기록에서 확인합니다. [과거 실행의 요청·응답 기록](openai.md#실행별-요청응답-기록)은 별도로 보존합니다.

## 브라우저 관찰의 수집 한도

[브라우저 자동 자산 연결](features.md#실제-브라우저-응답의-자산-연결)은 원문을 모델에 계속 추가하지 않고 필요한 식별 정보만 저장합니다.

| 구간 | 한도·동작 |
| --- | --- |
| 브라우저 메모리 | 대기 관찰 최대 2,000개, 중복 판별 키 최대 4,000개. 대기 상한 초과 시 오래된 관찰을 버리고 누락 수 표시 |
| DB 전달 | 한 배치 최대 100개. 저장 실패 시 커서를 진행하지 않아 다음 수집에서 같은 관찰을 재시도 |
| 도구 호출 후 수집 | 최대 4배치, 정상 클라이언트 종료 시 최대 20배치를 추가 수집. 각 수집은 최대 5초 |
| 의도별 DB 기록 | 정규화한 URL·메서드 기준 최대 1,000개. 상한 뒤의 새 주소는 생략 여부를 표시하며, 이미 남긴 후보의 등록 상태 갱신은 가능 |
| 모델에 전달 | 수집 건수와 사실 ID, 최대 20개 자산 ID. 전체 내용은 해당 관찰 사실로 조회 |

URL의 query는 기존 URL 규칙을 정확히 평가하기 위해 비공개 메모리와 내부 전달에만 남깁니다. 저장 전 사용자 정보·query·fragment를 제거하며, 관찰 대기열을 `session.json`에 기록하지 않습니다. 취소된 실행은 수집을 계속하지 않으므로 취소·프로세스 종료 전 DB에 저장되지 않은 관찰은 복원되지 않습니다. 이 한계는 이미 저장된 관찰 사실과 작업 보관·복원에 영향을 주지 않습니다.
