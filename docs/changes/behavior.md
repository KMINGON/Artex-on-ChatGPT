# 작업 방식과 설정

[변경점 전체 목록](../changes.md) · 비교 기준: ARTEX/global `fdfb7a1`

기본 탐색 방식은 원본과 같습니다. Goals가 목표를 분해하고 Planner가 방향을 배정하며 Worker가 실행합니다. Planner는 사실·발견과 Worker 결과를 읽어 후속 방향과 목표 달성을 판단합니다.

## 원본과 같은 작업 흐름

| 항목 | 현재 기본 동작 |
| --- | --- |
| 의도 배정 | Planner가 전체 범위와 목표를 보고 탐색 방향을 배정. Worker는 배정된 의도 수행 |
| 탐색 우선순위 | 원본의 깊이·경로 다양성·기존 결과 확인 지침 사용 |
| 재검증·기록 | 원본의 완료 방향·부정 결론 재검증·증분 기록 흐름 유지. 직접 관찰과 관측 범위를 넘는 추론 구분 |
| 완료 | 사실·발견으로 목표를 증명하고 목표 상태에 따라 종료. 별도 완료 검토나 미완료 질문 대장 요구 없음 |
| 도구 사용 | 원본 역할별 기본 도구 구성 유지. 브라우저는 활성 설정에 따라 제공 |
| 지침 언어 | 원본 의미의 한국어 기본 프롬프트와 선택한 출력 언어 사용 |

코드는 저장·취소·재개·오류를 일관되게 처리하지만 자연어 질문을 강제로 분할하거나 독립 검증 단계를 추가하지 않습니다. Planner Todo를 저장·복원하는 것은 이미 작성한 계획을 보존하는 기능이며 새 완료 조건이 아닙니다. 작업의 실제 행동에는 사용자 설명·목표·저장 프롬프트·활성 도구·모델 설정도 영향을 줍니다.

Worker 지침은 발견한 자산을 `insert_assets`로 등록하고 지문을 보완하도록 안내합니다. 자산을 파일이나 fact에 적는 것만으로 자산 그래프에 등록되지는 않습니다. 탐색 결론은 `record_fact`, 검증한 취약점은 `report_finding`으로 구분하며, 당장 테스트할 우선순위와 발견 자산의 등록 여부를 분리합니다. 배정된 의도 밖의 단서도 기록하고 다음 방향의 판단은 Planner에 맡깁니다.

Planner의 조회 예시는 실제 `list_assets` 필드·DSL과 그래프 응답을 따릅니다. 제공되지 않는 `asset_neighbors`나 SDK `Agent` 호출을 요구하지 않으며, 파일 검색은 현재 역할에 노출된 도구 또는 Bash의 `rg`·`find` 등으로 수행합니다. 목표·제약·힌트의 배치 스키마에는 기존 처리 필드를 표시하고 항목별 부분 성공을 유지합니다.

## 모델 선택과 연결 확인

**시스템 → LLM**에서 인증 방식과 계정을 고르고 모델을 조회한 뒤 연결을 확인합니다. 기존 설정은 저장된 키로 조회할 수 있으며, 계정·키가 바뀌면 이전 목록을 현재 권한처럼 사용하지 않습니다.

현재 입력으로 연결에 성공해야 프로필을 저장할 수 있습니다. 계정·모델·추론 강도·프로그램·프록시 등 입력이 바뀌거나 재확인에 실패하면 이전 성공 표시를 해제합니다. 늦게 도착한 요청도 변경된 입력의 결과로 표시하지 않습니다. 기본 모델이 없을 때 첫 사용 가능한 프로필을 기본으로 지정하고, 이후 변경은 사용자의 선택을 따릅니다.

모델 목록의 프로그램 지원 정보와 완료 응답에서 확인한 실제 프로그램을 구분합니다. 응답에 정보가 없으면 미확인으로 표시합니다. 명시한 모델·프로그램·인증 방식을 다른 값으로 바꾸어 연결 성공으로 처리하지 않습니다. [API·구독 차이](openai.md#api와-구독의-요청-차이)

## 작업·자원 설정 적용

작업 템플릿은 기존 생성 폼에 값을 채웁니다. 미지정·null은 현재 폼 값을 유지하고 명시한 `0`·`false`는 값으로 적용합니다. 이름·고급 설정을 저장할 수 있으며 템플릿 변경으로 이미 생성한 작업은 바뀌지 않습니다.

시스템 설정에서 Worker 수와 브라우저 상한을 조정하고, 작업 목록의 **동시 실행 설정**에서 동시 작업 상한을 조정합니다. 작업 생성 시 저장한 Worker 수와 서버 전체에 적용하는 동시 실행 상한을 구분합니다. [값과 적용 시점](../browser-and-presets.md#자원-설정)

## 작업 상태와 그래프 표시

| 화면 | 동작 |
| --- | --- |
| 탐색 그래프 | 최신 노드와 연결 이웃을 먼저 조회하고 이전 기록을 추가로 불러옴. 표시 건수·전체 건수 구분 |
| 관련 작업 | 직접 연결한 작업의 결과를 출처 ID와 함께 읽기 전용으로 조회 |
| 새로고침 | 펼친 페이지 범위를 다시 조회. 다른 작업으로 이동한 뒤 도착한 응답은 폐기 |
| 실행 시간 | 최초 실제 실행 시각이 있는 작업은 생성 후 대기 시간을 제외. 구형 기록은 기존 시각 사용 |
| 작업 상태 | 화면과 `list_tasks`에서 대기열·일시정지·모델 연결 상태를 같은 기준으로 계산 |
| Worker 진행 | 단계·도구·마지막 신호를 표시. 메모리 관측값으로, 완료 판정이나 영구 실행 이력이 아님 |
| 실행 설정 | 저장된 Worker 수와 현재 전역 브라우저 상한, 역할별 요청 모델·옵션을 구분 |

자산 관찰률은 fact/finding과 연결한 자산의 비율이며 취약점 유형별 검증 완료율이 아닙니다. 화면의 요청 설정도 과거 호출의 실제 응답값과 구분합니다.

## 언어와 저장된 사용자 값

한국어·영어를 지원하며 기본값은 한국어입니다. ARTEX 기본 프롬프트·규칙·오류 안내를 한국어로 제공하고 기계가 사용하는 도구 이름·JSON 키·상태값·템플릿 변수는 유지합니다. Norma와 일부 스킬에는 영어 안내가 남아 있으며, 실제 도구와 어긋나는 안내를 교정한 범위와 전체 번역을 구분합니다.

알려진 배포 기본값과 정확히 일치하는 항목만 이관합니다. 사용자 편집·선택한 과거 프롬프트 버전·활성 상태·삭제한 규칙을 보존하고, 과거 대화·대상 응답·외부 도구 출력을 일괄 번역하지 않습니다. 역할별 프롬프트는 전역 설정이므로 기본값 갱신은 기존 작업의 다음 Planner 회차·새 Worker 실행에도 적용될 수 있습니다.
