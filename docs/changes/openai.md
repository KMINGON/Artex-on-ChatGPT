# OpenAI 호환성과 API·구독 연결

[변경점 전체 목록](../changes.md) · 비교 기준: 한국어판 ARTEX/global `fdfb7a1`

API 키와 ChatGPT 구독은 같은 Responses 어댑터를 사용하지만 모델 카탈로그, 요청 옵션, 프로그램 접근 조건은 다릅니다. 조회 정보와 요청 설정, 실제 완료 응답을 따로 확인합니다.

## OpenAI·프로필 연결

| 항목 | 원본 | 현재 동작 |
| --- | --- | --- |
| OpenAI 대화 상태 | 표시용 텍스트·도구 이력 중심으로 reasoning 원형·`phase` 누락 | 완료 응답의 암호화 추론 상태·단계·항목 순서를 API·구독의 도구 왕복·저장·재개에 보존 |
| 프로필 활성화·적용 실패 | 키 없는 프로필도 활성화되며 이전 연결이 남을 수 있음 | 사용할 연결 없는 활성화 거부. DB 적용 확인 실패 시 HTTP 503으로 알리고 이전 연결로 새 요청 실행 차단 |
| 실행할 모델이 없는 작업 | 동시 실행 제한 설정에 따라 대기 없이 `model_error`로 실패 가능 | 연결 미설정 상태에서는 작업을 대기시키고 설정 안내 |
| 대화에서 만든 작업 | 대화의 모델을 생략하고 전역 모델로 실행 | 명시한 작업 모델·상위 작업 모델이 없으면 대화에서 선택한 프로필 상속 |
| 설정 변경 중 동시 요청 | 무효화한 이전 ChatAgent가 캐시에 다시 들어올 수 있음 | 캐시 세대 확인과 프로필 적용 동기화. 적용 후 새 요청부터 반영하고 진행 중 요청은 유지 |
| 도구 승인 Judge | `temperature=0` 강제가 기본 추론 설정과 충돌 가능 | 불필요한 temperature 지정 제거. 지원하지 않는 `reasoning=none`도 강제하지 않음 |
| 연결 테스트 출력 상한 | 테스트에서 고정된 `8192`를 사용해 실행 설정과 불일치 | API 프로필의 출력 상한으로 테스트. 추가한 구독 경로는 해당 필드 생략 |
| 구독 카탈로그 | ChatGPT 구독 연결 없음 | 계정·모델별 프로그램·추론 강도·기본값을 보존하고 필드 누락과 미지원 구분 |
| 구독 한도·계정 구분 | ChatGPT 구독 연결 없음 | 한도 차단을 연결 등록 단위로 보관하고 한도 재확인 성공 후 해제. 연결별 식별 라벨 표시 |
| 연결 결과·프로그램 | 프로그램별 지원 정보·실제 응답 표시 없음 | 입력 변경·확인 실패·늦은 응답을 구분하고 명시한 선택 보존. `access_programs: null`은 Standard, 필드 누락·빈 객체는 미확인으로 표시 |

**기존 OpenAI API에서도 일반 압축은 동작했습니다.** 개선한 부분은 누락되던 OpenAI 응답 상태 보존과 공통 실행 엔진의 압축·저장 처리입니다. 메시지를 편집·압축하면 원형 상태를 그대로 재사용할 수 없어 해당 opaque 상태를 제거합니다.

프로필 적용 중 DB 확인에 실패했다면 DB 연결을 복구한 뒤 프로필을 다시 저장하거나 활성화하세요. 연결 확인 기록은 표시용이며 실행 설정·권한을 대신하지 않습니다.

원본의 API 모델 조회를 유지하면서 **인증 방식별 조회 흐름과 모델 목록의 부가 정보를 설정에 연결**합니다. 구독 카탈로그의 `available_access_programs.cyber`·`supported_reasoning_levels`·기본 추론 강도를 전달하며, 프로그램 필드 누락과 Blue 미지원도 구분합니다. [모델 목록 처리](../../chatgptllm/catalog.go), [모델 기능 정보](../../chatgptllm/capabilities.go), 설정 화면 `web/src/app/(main)/system/llm/page.tsx`.

## API·구독 상세 동작

두 인증 방식의 모델 목록·프로그램 선택·실제 응답을 구분합니다.

### Daybreak 선택

공식 문서·API·구독 응답 확인일: **2026-10-23**. 모델과 접근 프로그램은 별도 값입니다. 모델 목록의 **선택 가능한 프로그램**, 프로필의 **요청 설정**, 연결 확인의 **실제 응답값**을 구분합니다. `-latest` 별칭이 폐지되었다고 해석하지 않으며, 기존 모델을 자동으로 다른 모델로 바꾸지 않습니다.

#### OpenAI API 키

**시스템 → LLM → 모델 설정 추가**에서 OpenAI API 키를 선택하고 키를 입력한 뒤 모델을 조회합니다. 조회 버튼이 모델 선택 목록으로 바뀌면 사용할 모델을 선택하고 **Daybreak 확인** 또는 **연결 확인**을 누릅니다. API 모델 목록은 그 키로 접근 가능한 모델 ID를 알려 주며, 모든 모델의 Responses 지원·추론 강도·Daybreak 권한까지 알려 주는 목록은 아닙니다. 조회된 모델의 기능 정보가 없으면 공식 문서 기반 옵션을 사용하고, 실제 적용 프로그램은 선택한 모델의 완료 응답으로 확인합니다. 목록 조회 단계에서 모든 모델에 추론 요청을 보내지는 않습니다. [API 모델 목록](https://developers.openai.com/api/reference/resources/models/methods/list)

새 API 설정은 프로그램을 생략해 서버의 기본 선택을 따릅니다. **Daybreak 확인**은 별도로 Blue를 강제하거나 다른 프로그램으로 재시도하는 버튼이 아닙니다. Standard 응답을 받았다고 모델·계정의 Daybreak 권한 전체가 없다고 단정하지 않으며, 네트워크·한도 오류도 Standard로 바꾸어 표시하지 않습니다. 직접 지정이 필요한 경우 **고급 설정 → API 액세스 프로그램**을 사용합니다.

| 선택 | 요청에 보내는 값 | 의미 |
| --- | --- | --- |
| 기본값 (필드 생략) | 필드 생략 | 모델·조직·프로젝트 권한에 따라 서버가 결정. **Daybreak 끄기와 다름** |
| `standard` (Standard) | `access_programs.cyber=standard` | 지원 모델에서 표준 보호 설정 명시 |
| `daybreak_blue` (Daybreak Blue) | `access_programs.cyber=daybreak_blue` | 해당 모델·프로젝트의 승인 필요 |
| `daybreak_red` (Daybreak Red) | `access_programs.cyber=daybreak_red` | 해당 cyber 모델과 별도 Red 승인 필요 |

`gpt-6-sol`의 Daybreak 값은 Blue입니다. `gpt-6.1-sol`·`gpt-6-astra`도 요청값은 Blue지만 조직의 **Red 승인과 프로젝트 접근 설정**이 필요하며, Red 값을 보내면 안 됩니다. `gpt-5.6-cyber`는 Red를 사용합니다. 프로그램 지정만으로 권한이 생기지 않습니다. [공식 Daybreak 안내](https://developers.openai.com/api/docs/guides/daybreak)

API의 모델별 지원 조합과 사용 권한은 OpenAI가 검증하고, 오류를 그대로 알립니다. ARTEX의 정적인 문서 정보가 더 최신인 계정 응답을 막지 않도록 백엔드는 프로그램 값의 형식과 구독의 명시 Blue·Red 제한을 검사합니다. 화면에서도 문서 목록에 없는 기존 값은 안내와 함께 유지하고 연결 확인을 허용합니다. 반면 계정 모델 목록이 명시한 지원값과 맞지 않는 설정은 직접 수정하도록 안내합니다. ARTEX가 다른 모델·프로그램·과금 방식으로 바꾸어 성공처럼 처리하지 않습니다. 연결 테스트에는 서버가 반환한 실제 모델과 접근 프로그램을 표시하며, 사용량 기록에도 해당 메타데이터를 보존합니다. 공식 응답의 `access_programs: null`은 Standard로 해석하지만 필드 자체가 누락되면 미확인으로 둡니다. [Responses API 요청 규약](https://developers.openai.com/api/reference/resources/responses/methods/create)

#### ChatGPT 구독

**연결한 계정의 모델을 조회하고 그 목록에서 선택**합니다. 계정 전체나 모델 이름으로 Daybreak 여부를 추정하지 않고, 해당 계정·모델의 `available_access_programs.cyber`로 화면을 구성합니다. `supported_reasoning_levels`는 추론 강도 선택지에 반영하고, `default_reasoning_level`은 기본값 안내에 표시합니다. 기본값 선택 시 요청에는 추론 강도를 보내지 않으며, 계정의 기본값을 사용자가 지정한 값처럼 저장하지 않습니다. 다른 계정이나 API 키의 목록은 구독 계정의 권한으로 사용하지 않습니다. [구독 모델·추론 안내](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

| 계정·모델이 제공한 프로그램 | 모델 목록의 태그 | 새 설정의 실제 요청 |
| --- | --- | --- |
| `standard`, `daybreak_blue` | **Daybreak** | `access_programs` 생략 |
| `standard`만 제공 | **Standard** | `cyber: "standard"` |
| `daybreak_blue`만 제공 | **Daybreak** | `access_programs` 생략 |
| 조회 전 또는 프로그램 정보 누락 | **미확인** | `access_programs` 생략 |

목록의 **Daybreak 태그는 계정 카탈로그의 지원 정보**이고, 연결 후 표시하는 프로그램은 **실제 완료 응답**입니다. 둘이 다르면 실제 응답을 우선 표시하고 차이를 안내합니다. 프로그램 생략은 서버의 선택을 따르므로, 조회에서 Daybreak를 지원한다고 확인한 것만으로 매 호출의 적용값까지 확정하지 않습니다.

기존에 Standard를 명시한 구독 설정은 모델·계정 변경만으로 자동 선택으로 바꾸지 않습니다. 해당 모델에서 자동 선택이 가능하면 기존 Standard 유지 안내와 **자동 선택으로 변경** 버튼을 표시합니다. 사용자가 전환하면 다시 연결을 확인한 뒤 저장합니다. 기존 빈값은 지원 정보가 Standard만 제공하는 것으로 확인되면 Standard로 맞춥니다. API도 모델을 바꿔도 사용자가 명시한 프로그램 선택을 유지하며, 새 모델과의 호환성은 연결 확인으로 검증합니다.

현재 SIWC 경로는 **생략 또는 명시적 Standard**를 지원하도록 구성했습니다. 구독에서 Blue·Red를 명시하는 설정은 허용하지 않습니다. 개발 과정의 실제 구독 계정 시험에서 GPT-6 Sol은 프로그램 생략 시 Blue, Standard 명시 시 Standard를 반환했으나, Blue 명시 시에는 Standard를 반환했습니다. Astra·6.1 Sol은 같은 계정에서 Standard만 조회되었고 Blue 명시 요청은 거부되었습니다. 이 관측은 해당 계정·시점의 SIWC 호출 결과이며, 일반 API 키 경로의 결함이나 모든 계정의 동작으로 해석하지 않습니다.

Codex에도 별도의 [Daybreak 선택 기능](https://help.openai.com/en/articles/20001607-using-daybreak-in-codex-cli)이 있습니다. ARTEX는 Codex를 실행하거나 내부 호출 주소로 우회하지 않고, 공식 SIWC의 공개 Responses 경로를 계속 사용합니다. 반환 프로그램이 요청 의도와 다르면 실제 응답값을 표시하며, 다른 모델·인증 방식으로 몰래 바꾸지 않습니다.

### API와 구독의 차이

| 항목 | OpenAI API 키 | ChatGPT 구독 |
| --- | --- | --- |
| 사용량·과금 | API 프로젝트의 과금·한도 | 연결한 ChatGPT 계정의 요금제·앱 사용 한도 |
| `temperature` | 내부 호출에서 지원 조건에 맞는 경우 전달. Judge는 강제값 제거 | 전송하지 않음 |
| `max_output_tokens` | 서버 출력 상한 전달 | 전송하지 않음. 보조 요청에 간결한 출력 지시·로컬 시간/수신량 제한 적용 |
| 모델 조회 | 입력한 키 또는 저장된 키로 조회. 기능·프로그램 권한은 목록에 없는 경우가 있음 | 선택한 계정의 모델·프로그램·추론 옵션을 함께 조회 |
| 추론 강도 | 모델 목록의 기능 정보 또는 공식 문서 기반 선택지. 실제 지원은 OpenAI가 검증 | 계정 모델의 지원값으로 선택지 구성하고 기본 추론 강도 안내. 기본값 생략과 `none`은 서로 다름 |
| Daybreak | 기본값은 서버 선택. 선택한 모델의 실제 연결로 확인하며 고급 설정에서 프로그램 명시 가능 | Blue가 제공된 모델에 **Daybreak** 태그, 요청은 필드 생략. Standard만 제공하는 모델은 명시 전송 |
| 연결·저장 | 실제 모델·프로그램을 확인한 뒤 저장. 카드에 마지막 확인 결과 표시 | 동일. 목록의 지원 태그와 실제 응답이 다르면 안내 |
| 도구·입력 | 텍스트·로컬 function·MCP, 도구 결과와 `Read`의 이미지 | 동일한 이미지 변환 사용. 채팅 이미지 업로더·OpenAI 호스팅 도구는 미구현 |
| 응답 상태 | reasoning·`phase`·항목 순서를 완료 응답에서 보존 | 동일한 어댑터·저장 형식 |
| 실패·전환 | 명시적으로 설정한 API 프로필 전환 정책 유지. 원형 상태가 있으면 다른 연결로 자동 재전송 차단 | 유료 API 키 경로로 자동 전환하지 않음 |

구독의 로컬 제한은 서버의 생성 토큰·추론 비용 상한을 대체하지 않습니다. 도구가 없고 호출자가 추론 비활성화와 출력 토큰 수를 요청하는 보조 호출에만 90초와 8–64KiB 수신 제한을 적용합니다. 무작위성 제어나 추론 완전 비활성화를 복원하는 기능이 아닙니다. [SIWC 미리보기 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

한도 오류 후에는 ChatGPT Usage 설정을 확인하고 ARTEX의 **한도 재확인**을 사용합니다. 한 번의 실제 추론을 허용하는 검사로 사용량이 발생할 수 있으며, 성공해야 신규 요청을 다시 허용합니다. 재시작·토큰 갱신만으로 한도가 풀렸다고 간주하지 않고, 계정의 전체 잔량이나 리셋 시간을 추정하지 않습니다. [오류·복구 안내](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)

OpenAI 스트림은 헤더·본문 읽기에 15분 동안 바이트가 없을 때 대기를 취소합니다. keepalive가 오거나 정상 장기 추론·도구 실행 중이면 이 무신호 제한으로 종료하지 않습니다. HTTP 200만으로 성공을 판정하지 않고 완료 이벤트와 실패·미완료 이유를 확인합니다. 실패한 응답에도 사용량이 실제로 도착하면 누적하며 미수신과 실제 0을 구분합니다.

출력을 전달하기 전의 `server_is_overloaded` 등 알려진 일시 오류는 재시도 상한 안에서 같은 연결·요청으로 다시 시도합니다. 서버가 양의 초 단위 `Retry-After`를 주면 그 시간만큼 기다리며 취소 요청을 따릅니다. 출력이 시작된 요청이나 실행한 도구를 자동 재생하지 않고, 사용 한도·인증·알 수 없는 오류를 일시 장애로 간주하지 않습니다. [오류 분류](../../chatgptllm/errors.go), [요청·재시도 처리](../../chatgptllm/provider.go)

## 실행별 요청·응답 기록

LLM 원문 녹화가 꺼져 있어도 `llm_usage.metadata`에 비교용 실행 정보를 남깁니다. [`llmrec/llmrec.go`](../../llmrec/llmrec.go)의 `runtimeMetadata`는 요청 모델·설정한 추론 강도·프로그램·인증 방식·빌드 버전, 요청별 Thinking·출력 상한·지정한 temperature, 조립한 시스템 지침과 도구 정의의 SHA-256, 도구 이름을 저장합니다. 어댑터에서 관측한 실제 모델·프로그램 등 응답 메타데이터는 별도 `response` 필드로 보존합니다. 설정값과 요청별 추론 활성 여부를 함께 보며, 이 기록 자체가 서버의 실제 적용값을 뜻하지는 않습니다.

원문 시스템 프롬프트·도구 인자·자격증명을 이 비교 메타데이터에 복사하지 않습니다. 요청한 출력 상한은 `max_output_tokens_requested`로 기록하지만 구독 경로에서 서버에 전송했다는 뜻은 아닙니다. 이전 행에 값이 없으면 사후에 추정하여 채우지 않습니다. 화면의 [현재 실행 설정](behavior.md#작업-상태와-그래프-표시)과 과거 호출의 설정을 구분해 비교할 수 있습니다.
