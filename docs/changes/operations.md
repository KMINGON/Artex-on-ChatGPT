# 설치·운영

[변경점 전체 목록](../changes.md) · 비교 기준: ARTEX/global `fdfb7a1`

현재 소스로 앱·웹·로컬 Norma를 함께 빌드하는 Compose 구성을 제공합니다. 기존 작업과 사용자 설정을 유지하면서 실행 환경·저장 형식·기본값을 갱신합니다. 빠른 설치는 [README](../../README.md#빠른-시작)를 참고하세요.

## 실행 환경

| 원본 대비 변경 | 현재 구성 |
| --- | --- |
| 앱·DB 설치 | Docker Compose로 앱과 PostgreSQL 16 실행. 이미지가 없으면 현재 소스로 빌드 |
| 실행 엔진 | `go.mod`의 로컬 replace로 `third_party/norma`를 함께 빌드 |
| 브라우저 | Chromium·Playwright·NSS 인증서 도구 포함. Compose의 `init`과 1GiB 공유 메모리 사용 |
| 인증 저장 | ChatGPT 자격증명·관리자 서명 키·브라우저 프로필을 별도 인증 볼륨에 보관 |
| 접속 | 웹 게시 주소와 대상 접속 주소 구분, `host.docker.internal` 호스트 게이트웨이 제공 |

Compose의 기본 웹 주소는 `0.0.0.0:8787`입니다. DB와 기록 프록시 포트는 호스트에 게시하지 않습니다. `ARTEX_BIND_IP=127.0.0.1`로 이 PC에서만 접속하도록 바꿀 수 있습니다. 앱 안에서 실행하는 도구의 `127.0.0.1`은 ARTEX 컨테이너이며, 대상 주소는 [접속 주소 표](../../README.md#접속-주소)를 따릅니다.

`.env`는 선택 사항입니다. 새 DB는 사용자·이름 `artex`, 비밀번호 `artex-local-db`로 준비하고, 최초 관리자 계정은 `ARTEX` / `artex1234`입니다. `ARTEX_ADMIN_PASSWORD`는 비밀번호가 없는 설치에만 적용됩니다. 기존 관리자 비밀번호나 PostgreSQL 볼륨의 접속 정보는 환경변수 변경으로 초기화되지 않습니다. [환경변수 예시](../../.env.example), [Compose 설정](../../docker-compose.yml)

ChatGPT 로그인 콜백은 공유 웹 포트의 `http://127.0.0.1:${ARTEX_PORT:-8787}/auth/callback`을 사용합니다. Docker를 실행한 PC의 브라우저에서 관리자 로그인 후 ChatGPT 계정을 연결합니다. 연결 해제와 서버 재시작은 별개이며, 재시작해도 저장한 연결이 유지됩니다.

## 호스트 설치

Docker를 사용하지 않는 빌드 경로도 유지합니다. Go 1.26.3 이상, Node.js 24, npm, rsync, PostgreSQL을 준비합니다. 관리 브라우저를 사용하려면 Playwright·Chromium과 실행 라이브러리도 별도로 준비해야 합니다. Docker 이미지는 이 구성요소를 함께 제공합니다.

```sh
ARTEX_OUTPUT=./artex ARTEX_BUILD_VERSION=openai-local ./build.sh --no-compress
export ARTEX_PG_DSN='postgres://artex:비밀번호@127.0.0.1:5432/artex?sslmode=disable'
ARTEX_LANG=ko ./start.sh
```

`ARTEX_PG_DSN`이 우선하며, 명시적인 `ARTEX_PG_HOST`와 개별 DB 환경변수, 설정 파일 순으로 연결 설정을 읽습니다. 관리자 초기 비밀번호를 지정하지 않은 호스트 설치는 콘솔의 설정 토큰으로 초기 설정을 진행합니다. [설정 예시](../../config.example.json)

## 데이터와 업데이트

| 저장소 | 보관 내용 |
| --- | --- |
| `pgdata` | 작업·그래프·설정·프로필·증거 연결 |
| `artex-data` (`/app/data`) | 대화 기록·작업 파일·이미지·트래픽 증거 본문 |
| `artex-auth` (`/app/auth`) | ChatGPT 자격증명·관리자 서명 키·브라우저 프로필 |

같은 Compose 프로젝트는 볼륨을 재사용합니다. 업데이트 전 세 저장소를 함께 백업하고 `git pull --ff-only`, `docker compose up -d --build`로 소스와 이미지를 갱신합니다. `docker compose stop`과 `down`은 볼륨을 보존하지만 **`docker compose down -v`는 해당 프로젝트의 세 볼륨을 삭제**합니다. 별도 호스트 DB나 인증 폴더를 자동으로 옮기지는 않습니다.

ChatGPT 자격증명은 PostgreSQL에 저장하지 않습니다. Compose에서는 `/app/auth/artex-on-chatgpt/`, 호스트에서는 기본적으로 `~/.config/artex-on-chatgpt/`에 보관하며 폴더 `0700`·파일 `0600` 권한을 사용합니다. 브라우저 프로필도 인증 저장소에 두고 일반 작업 파일 목록에 노출하지 않습니다.

대화 체크포인트는 완성된 묶음만 적용합니다. 알려진 미완성 저장은 원본 JSONL을 보존한 채 `.recovered` 파일로 복구하고, 마지막 정상 체크포인트 뒤의 실제 메시지도 유지합니다. 일반 손상이나 알 수 없는 형식은 임의로 덮어쓰지 않습니다. 작업 보관·복원에는 복구 파일과 하위 세션을 포함하며, 작업 삭제 시 해당 작업의 소유 파일을 정리합니다. 새 저장 형식의 세션을 구버전 바이너리와 동시에 쓰지 마세요. [Norma 저장 처리](../../third_party/norma/ARTEX_PATCHES.md)

## 기존 설정의 이관

| 항목 | 적용 조건과 보존 범위 |
| --- | --- |
| 프롬프트·도구·규칙 | 알려진 배포 기본값과 정확히 일치하는 값만 갱신. 사용자 편집·비활성 상태·삭제·이관 후 선택한 과거 버전 보존 |
| 작업 템플릿 | 자동 기본 템플릿을 생성하지 않음. 과거에 자동 등록한 것으로 식별되고 필드와 본문이 그대로인 템플릿만 제거하며, 사용자 수정·직접 작성 템플릿과 기생성 작업은 보존 |
| 구형 정책 필드 | 원문 JSON을 보존하고 설명·기존 동작 제약으로 한 번 이관. 보관 작업은 복원 시 같은 처리 |
| 자원 프리셋 | 사용자가 선택할 때 Worker·동시 작업·브라우저 수만 적용. 도구·트래픽·모델·인증 설정은 유지 |
| 브라우저 | 새 설치의 기본 MCP는 활성화. 기존 명시적 비활성화·사용자 지정 인자는 유지 |
| 기존 저장 자료 | 그래프·증거·과거 브라우저 관찰의 조회·보관·복원 호환 유지. 브라우저 응답에서 그래프 관찰을 자동 생성하지 않음 |

역할별 시스템 프롬프트는 전역 설정입니다. 기본값이 갱신되면 기존 작업의 다음 Planner 회차나 새 Worker에도 적용되지만, 이미 저장한 작업 설명을 템플릿으로 덮어쓰지는 않습니다. [작업 방식과 설정](behavior.md)

## 제거한 구성과 출처

OpenAI 전용 구성에 맞춰 Claude·Chat Completions·임의 LLM 주소·DeepSeek 전용 경로와 실험적 Noa를 제거했습니다. 기본 대화 압축과 탐색 그래프 요약은 유지합니다. 기존 Noa 상태는 적용하지 않지만 저장된 대화·아카이브를 일괄 삭제하지 않습니다.

실행과 무관한 별도 탐지 자료, 과거 벤치마크·설치 스크립트, GitHub 워크플로와 미사용 웹 언어는 제거했습니다. 현재 언어는 한국어·영어이며, 기존 다른 언어 설정은 한국어로 정규화합니다. 일반 도구·스킬·가로채기·트래픽 증거·자동 보고서 등 원본 기능은 해당 실행 경로에서 유지합니다.

`github.com/Autumn-27/artex`는 Go 모듈 이름이며 런타임에 원본 코드를 다운로드하는 주소가 아닙니다. 수정한 Norma는 로컬 소스로 빌드합니다. 원저자·모듈·라이선스 고지는 보존하며, 출처와 조건은 [README](../../README.md#출처와-라이선스)와 [Norma 문서](../../third_party/norma/ARTEX_PATCHES.md)에 있습니다.
