# 오류·상태 보존

[변경점 전체 목록](../changes.md) · 비교 기준: ARTEX/global `fdfb7a1`

원본의 작업 배정·탐색 판단을 유지하면서 도구 호출, 그래프 저장, 실행 결과 전달, 대화 재개에서 발생하는 오류와 상태 유실을 보완합니다. 구독·관리 브라우저의 추가 기능은 [연결·기능](features.md)과 구분합니다.

## 도구·취약점 등록

| 영역 | 원본 대비 변경 |
| --- | --- |
| 선택 인자 | `report_finding.evidence_hint_id`의 생략·null·0을 미지정으로, `traffic_refs: null`을 연결 없음으로 처리 |
| 스키마 | nullable·union과 `required`의 Go/JSON 배열 표현을 처리하고 하위 필수 필드 검사는 유지 |
| 배치 입력 안내 | 목표·제약·힌트 배열에 기존 처리 필드를 노출. 기존 항목별 오류 처리에서 유효 항목의 저장·반환 순서와 실패 항목 `id=0` 유지 |
| 지연 실행 | `ExecuteExtraTool`의 `params`·`parameters`를 호환. 함께 전달한 값이 다르면 실행하지 않음 |
| 입력 오류 | 현재 도구의 필수 필드·타입 안내. 누락 값을 만들어 실행하거나 다른 내부 필드로 임의 변환하지 않음 |
| 출력 캡처 | 출력 속 marker 문자열을 신뢰하지 않고 같은 호출에서 실제로 캡처한 결과만 중복 처리에서 제외 |
| 검색 | `Grep.only_matching`으로 긴 한 줄 파일의 일치 부분을 반환. 기본 출력은 유지하며 원본 역할별 도구 노출을 변경하지 않음 |
| 실행 이력 | `get_worker_trace.returned_step_ids`와 안내 개수를 실제 반환 단계에 맞춤. 다른 의도·출처의 단계나 없는 ID를 반환한 것으로 표시하지 않음 |
| 스킬 안내 | ScopeSentry 헤더를 정상 해석해 준비 절을 전달. API 조사에서 mock·업무 코드·네트워크 전달 범위를 구분하고 브라우저 스킬의 설치·세션·인증 복원 안내를 실제 동작에 맞춤 |

실제 지정한 근거·자산·트래픽 ID는 유효성과 귀속을 확인합니다. 잘못된 값을 조용히 무시하지 않습니다. 취약점 ID와 탐색 노드 ID의 사용처는 [트래픽 증거 안내](../finding-traffic-evidence.md)에 설명합니다.

## 그래프 기록과 결과 전달

| 영역 | 현재 보존하는 내용 |
| --- | --- |
| 사실 등록 | 실제 실행 의도에 귀속하며 사실과 `yields` 연결을 함께 저장. 다른 Worker의 의도 ID 사용 거부 |
| 의도·자산 등록 | 노드·부모·자산 앵커·작업 출처·범위를 트랜잭션으로 저장. 부분 실패를 성공으로 반환하지 않음 |
| 목표 증명 | 근거·이유·시각, `proves` 연결과 목표 상태를 함께 저장. 목표 내용이 바뀌면 이전 증명을 무효화 |
| Planner Todo | 작업에 revision과 함께 저장. 늦은 이전 쓰기가 새 계획을 덮어쓰지 않도록 확인 |
| Worker 결과 | 실행 경계·ID로 현재 회차의 최신 결과 조회. 준비 실패 전에 남은 과거 성공 결과와 늦은 이전 결과 구분 |
| 결과 인계 | Worker 결과 전문과 관련 파일 참조를 전달하여 원본의 짧은 인계에서 잘리던 내용 보존 |
| Planner 실패 | 실패·취소한 회차의 종료 이벤트를 다음 정상 회차에 다시 전달. Worker 도구를 다시 실행하지 않음 |
| 공유 파일 | 작업 공용 경로와 개별 의도 경로를 구분해 다른 Worker·Planner가 같은 파일을 찾도록 연결 |
| 시작 자산 | 실행 전에 자산 조회·범위 저장 오류를 확인. 여러 자산의 일부 범위만 저장한 채 진행하지 않음 |

완료 시 목표 상태 변경·일시정지·재개의 동시 쓰기를 조율합니다. 원본처럼 Planner가 목표를 증명하며 별도 `completion_review`·Todo 완료 게이트는 요구하지 않습니다. 새 목표·의도 재개에 따른 작업 상태 변경과 오류 전달을 탐색 내용의 추가 심사로 대체하지 않습니다.

IP 주소로 접근한 URL의 범위와 관찰률 계산을 맞추고, 시작점·기각된 항목을 실제 관찰로 계산하지 않습니다. 탐색 그래프는 최신 페이지·전체 건수·커서와 연결 이웃을 제공해 오래된 고정 개수 조회로 최신 결과가 가려지는 문제를 보완합니다.

관련 구현: [`db/graph_mutations.go`](../../db/graph_mutations.go), [`db/asset_observations.go`](../../db/asset_observations.go), [`db/planner_state.go`](../../db/planner_state.go), [`db/worker_result.go`](../../db/worker_result.go), [`agent/tools.go`](../../agent/tools.go).

## 대화·요약·재개

- 대화 압축에서 도구 호출·결과 쌍과 저장 파일 참조를 보존합니다. 요약 전에 오래된 결과 본문을 지우지 않습니다.
- 요약 요청이 너무 크면 완전한 API 회차 경계로 나누어 전체 구간을 읽습니다. 앞부분을 버려 크기만 줄이지 않으며, 한 구간이라도 실패하면 원문을 유지합니다.
- 정상 완료한 요약만 적용하고, 취소·빈 본문·출력 한도·입력 크기 비감소를 구분합니다. 현재 메시지·도구 정의·system 비용을 문맥 계산에 반영합니다.
- 대화 파일은 완성된 checkpoint만 채택합니다. 알려진 부분 저장은 원본을 보존한 복구 파일로 재개하고, 일반 손상은 오류로 알립니다.
- Worker·Chat·Main의 마지막 성공한 TodoWrite를 대화에서 복원합니다. 실패·미완료 호출과 중복 checkpoint는 새 계획을 덮어쓰지 않습니다.
- 그래프 요약에 상세 payload·증거·자산·계보를 전달합니다. 입력이 불완전하거나 원문이 바뀐 요약은 원본을 대신하지 않으며 큰 노드는 원문 조회 경로에 남깁니다.

관련 구현과 저장 형식은 [Norma 원본 대비 변경점](../../third_party/norma/ARTEX_PATCHES.md)에 있습니다. 모델이 생성한 요약의 모든 의미가 완벽하게 보존된다는 보장은 없습니다. 전체 자료 보존은 더 큰 입력이나 추가 구간 요약 비용을 수반할 수 있습니다.

## 취소·종료·자동 실행

취소된 도구 묶음은 원래 context를 유지하며, 대기 중이던 도구가 마무리 단계의 새 context로 실행되지 않습니다. 잘린 도구 인자를 실행하지 않고 출력 연장 한도 소진은 정상 완료와 구분합니다. 저장 실패는 실행·종료 호출부까지 전달하여 성공으로 표시하지 않습니다.

자동 트리거는 미실행 대기 항목과 처리 위치를 함께 저장해 재시작 후 복구합니다. 이미 실행을 시작한 뒤 결과가 불명인 요청은 중복 효과를 피하기 위해 자동 재실행하지 않습니다. 실행 전 연결 미설정·로그아웃·확인된 구독 한도 차단은 대기 상태를 유지합니다.

취소가 이미 발생한 도구의 효과를 되돌리지는 않습니다. 전체 모델 실행이나 완료된 도구를 오류 복구 명목으로 반복하지 않습니다.

## 연결·프록시·가로채기

| 영역 | 현재 동작 |
| --- | --- |
| 브라우저 런타임 | MCP·Playwright·Chromium을 같은 설치로 실행하고 기록 CA를 Chromium에 전달 |
| API 조사 스크립트 | 설치된 Playwright 사용, proxy·쿠키 전달과 모의 응답 출처 표시 |
| WebFetch | 본문 수신 실패를 오류로 알리고 수신 한도·표시 한도 구분. 지정한 기록 프록시 장애만 우회하며 외부 프록시는 유지 |
| 스트림 기록 | SSE·큰 응답을 끝까지 버퍼링하지 않고 메타데이터·본문 생략·완료 불명 상태 기록 |
| MCP 종료 | 초기화 실패·종료 시 하위 프로세스 정리, 초기 연결 대기에 취소 전파 |
| 차단 집계 | 대상 응답의 403·blocked 문자열과 실제 ARTEX 실행 전 차단을 구분 |
| Shell 규칙 | `Bash.command`·`shell_open.command`·`shell_send.text`를 검사. 파일 본문·설명에 든 명령 문자열을 실행으로 오인하지 않음 |

가로채기의 기본 정책과 사용자 규칙을 유지합니다. 사용자 지정 `tool_input` 규칙은 계속 전체 인자를 검사합니다. Shell 규칙은 정규식이며 완전한 셸 해석기가 아니므로 인용 문자열·외부 스크립트의 의미까지 판정하지 않습니다. OpenAI의 응답·연결 오류 처리는 [OpenAI 처리](openai.md)에 별도로 정리합니다.
