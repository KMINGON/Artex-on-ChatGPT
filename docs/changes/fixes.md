## 버그·호환성 수정

### 브라우저·이미지·프록시

| 항목 | 원본 | 현재 동작 |
| --- | --- | --- |

| 가로채기 적용 | Planner·MainAgent 일부 도구 경로에 공통 훅 누락 | 공통 가로채기 훅과 작업 ID 전달. 기본 도구 범위는 원본을 유지하고 사용자가 명시 선택한 MCP 그룹에도 적용 |

시스템 명령 기본 규칙은 `shell_command` 대상으로 `Bash.command`·`shell_open.command`·`shell_send.text`만 검사합니다. 파일을 작성하는 `Write`의 소스 코드에 `halt`·`reboot` 같은 문자열이 들어 있다고 명령 실행으로 오인하지 않습니다. 정규식·우선순위·차단 동작은 유지하며, 사용자 지정 `tool_input` 규칙은 계속 전체 도구 인자를 검사합니다.

이 검사는 셸 구문 해석기가 아닙니다. 인용된 문자열이 정규식에 걸릴 수 있고 외부 스크립트 파일의 내용이나 임의 MCP 실행기의 의미까지 해석하지 않습니다. SQL·HTTP DELETE 규칙도 별개로 유지합니다. 알려진 기본 규칙만 이관하며 사용자 수정·비활성화·삭제는 보존합니다. [`intercept/intercept.go`](../../intercept/intercept.go), [`db/intercept_shell_defaults.go`](../../db/intercept_shell_defaults.go)

### 작업 템플릿·설정

원본의 작업 템플릿을 확장한 4종 기본 프리셋은 허용 범위·탐색 근거·미완료 질문·완료 조건을 설명과 목표에 담습니다. 작업 이름과 고급 설정을 저장하며 미지정·null·0·false, 초 단위 시간값을 구분합니다. 최초 등록 후 사용자 수정·삭제와 이미 생성한 작업을 보존하고, 적용 후 사용자가 편집한 최종값을 기존 생성 API로 전달합니다. [프리셋의 최종 동작](features.md#브라우저이미지프리셋), [사용법과 데이터 호환](../browser-and-presets.md#작업-프리셋)을 참고하세요.

요약은 원문보다 짧은 모델 산출물이므로 모든 의미를 완벽히 보존한다고 보장할 수 없습니다. 호출이나 결과 한쪽만 남은 도구 교환은 성공으로 추정하지 않고 미확인 자료로 요약에 전달합니다. 분할할 수 없는 단일 회차가 너무 크면 요약을 중단하고 원문을 남깁니다. 전체 자료를 읽는 요약과 Todo 복원 안내로 입력량·처리 시간이 늘어날 수 있습니다. [`third_party/norma/compaction`](../../third_party/norma/compaction/compaction.go), [`Todo 복원`](../../third_party/norma/tool/todo.go)

취소는 이미 끝난 도구의 효과를 되돌리지 않습니다. 취소를 무시하는 외부 프로그램까지 모두 즉시 정지시킨다는 보장도 아닙니다. 자동 트리거는 **실행 전 대기 상태만 복구**합니다. 이미 실행을 시작한 상태에서 서버가 종료되면 결과 불명으로 남기며, 도구의 중복 실행을 피하기 위해 자동 재실행하지 않습니다. 대화 기록을 확인한 후 사용자가 재시도해야 합니다. 실행 전에 연결 미설정·로그아웃·기록된 한도 차단을 확인하면 대기 항목을 유지하고 연결 복구 후 다시 시도합니다. 원본 작업이 삭제·보관되면 미실행 항목은 취소하며 작업을 복원해도 자동으로 재발행하지 않습니다.

HTTP 200 이후에도 SSE의 `response.failed`·`error`로 요청이 실패할 수 있습니다. 오류 코드·요청 ID·단계·요청 크기를 기록하며, 출력·도구 실행 후 전체 작업을 자동 반복하지 않습니다. `Output too large` 파일 안내 자체가 모델 컨텍스트 초과를 뜻하지는 않습니다. 원본 HTTP 본문·암호화 추론·자격증명은 진단 로그에 넣지 않습니다.

## 그래프·에이전트 인계

자산 그래프와 탐색 그래프의 기존 구조를 유지하면서 기록·연결·후속 조회가 함께 성공하도록 정비했습니다.

| 원본의 문제 | 현재 동작 |
| --- | --- |
| 사실의 `intent_id`를 생략하면 Worker가 만든 결과에 생산 의도 연결이 없고 다른 Worker ID를 넣을 수도 있었음 | 실제 실행 의도로 기본 귀속하고 다른 Worker의 ID는 거부. 사실과 필수 `yields` 연결을 한 트랜잭션에 저장 |
| 의도·사실 등록 후 연결 실패를 무시할 수 있었음 | 노드·부모·자산 앵커를 함께 저장하고 실패 시 전체 롤백. 초기 의도와 모델 없는 수동 의도도 같은 등록 경로 사용 |
| Planner의 `parent_ids` 안내가 의도 ID를 허용하는 것처럼 보이지만 도구는 fact/finding만 허용 | 기본 지침·도구 스키마를 실제 규칙에 맞춤. 잘못 전달한 의도 ID에는 실제 결과 노드 ID를 안내 |
| 목표 증명 이유가 저장되지 않고 연결·상태 갱신 오류를 무시 | 근거 노드·이유·시각과 `proves` 연결·목표 상태를 함께 저장. 동시 증명도 같은 잠금 아래 판정 |
| 달성한 목표의 내용을 수정해도 이전 달성 상태가 남고 payload를 통째로 교체 | 내용이 바뀌면 기존 증명·완료 검토를 원자적으로 무효화해 다시 열고 다른 사용자 payload는 보존 |
| 마지막 판정 뒤 들어온 작업이나 같은 의도의 재개를 완료 처리와 함께 조율하지 못함 | 열린·실행 중·일시정지 의도가 있으면 마지막 목표 증명 거절. 완료 직전 목표·의도·새 사실·발견·Todo를 재검사하며 상태 변경·재개·보관이 같은 작업 잠금을 공유 |
| 종료한 작업에서 일시정지 의도를 재개하면 의도만 open으로 바뀌거나 DB·메모리 전환 사이에 재개가 누락 | 작업 admission을 거쳐 재개하고 실패 시 의도 상태 복원. 사용자 pause·FIFO 대기 순서와 완료 후 새 목표를 보존 |
| `insert_assets`의 자산 저장 뒤 출처·앵커·범위 저장 실패를 무시 | 항목마다 자산·작업 출처·탐색 앵커·범위를 한 트랜잭션으로 저장. 배치 결과의 항목별 오류 유지 |
| Worker가 시작 자산 조회·자동 범위 저장 실패를 무시하고 실행 | 시작 자산과 범위를 작업 잠금 아래 준비하고, 실패 시 모델 호출 전에 저장 오류로 종료. 여러 자산의 부분 범위 저장 방지, 커버리지 비활성 시 자산 조회만 유지 |
| IP 주소를 직접 쓴 URL은 별도 IP 필드를 주지 않으면 범위 집계에서 빠질 수 있었음 | URL의 IPv4·IPv6를 정규화해 `/32`·`/128` 범위를 저장하고 조회 조건과 일치시킴 |
| 시작점·기각된 사실도 관찰 결과로 계산하고 finding만 연결한 자산은 집계하지 않음 | 시작점·기각 항목을 제외한 fact/finding으로 자산 관찰률 계산. 현재 작업·직접 연결된 작업·미관찰 목록·그래프의 기준 통일 |
| Planner Todo가 프로세스 메모리에만 있어 모델 교체·재시작 때 사라질 수 있었음 | 작업 시작 노드에 revision과 함께 저장. 늦은 이전 Planner 쓰기는 충돌로 거절하고 최근 계획 유지 |
| 작업자별 상대 경로 때문에 다른 Worker나 Planner가 같은 공유 파일을 찾지 못함 | `task_root/shared`와 `intent_dir`를 구분하고 인계에 절대 경로 사용. 개별 증거·브라우저·인증 격리는 유지 |
| 작업 결과 조회가 실행 과정 앞부분에 의존해 긴 실행의 최종 결과를 놓침 | 준비·모델 실행 경계와 실행 ID로 현재 회차의 최신 `result`, 없으면 최신 `text` 조회. 이전 회차의 늦은 결과와 준비 실패 전 성공 결과를 현재 결과로 사용하지 않음 |
| 탐색 그래프의 오래된 노드 2,000개·연결 5,000개 제한이 화면에서 드러나지 않음 | 최신 페이지·전체 건수·커서와 연결 이웃을 제공하고 웹에서 과거 기록 확장 |
| 무제한 작업의 최초 실행 시각이 없고 웹·도구 상태 계산도 서로 다름 | `timeout=0`에도 최초 실행 기록, 웹과 작업 조회 도구가 같은 상태 계산 사용 |
| 그래프 요약이 summary 중심 입력으로 상세·증거를 보지 못한 채 원본 노드를 대표함 | 상세·증거·후속 단서·구조화 관찰 등 전체 payload와 자산·계보 연결을 노드 단위로 입력. 입력 예산보다 큰 노드는 생략 요약으로 덮지 않고 원본으로 조회 |

그래프 요약은 완전한 입력으로 생성되었고 현재 원문·자산·계보 연결과 일치할 때만 원본을 대표합니다. 노드·버전·연결을 같은 DB 스냅샷에서 읽고 저장 직전 변경을 다시 확인합니다. `input_complete`는 생성 당시 입력의 완전성, `source_current`는 현재 원문·연결과의 일치 여부입니다. 불완전한 옛 요약·변경된 노드·초과 크기 노드는 원문 조회 경로에 남기며, 오래된 요약을 조회할 때도 원문 우선 안내를 제공합니다. 새 요약 생성·저장이 실패하면 기존 자료를 유지합니다. 고정된 짧은 출력 상한을 두지 않지만 백그라운드 요약의 5분 제한은 유지합니다. 개요의 항목 수와 사실 목록의 페이지 범위 밖 자료는 `list_facts`·`node_detail`, 요약 전문은 `expand_digest`로 읽습니다.

Worker 결과는 원본의 800자 인계 제한 없이 Planner에 전달합니다. `get_worker_output`은 의도 상태·출력 종류·현재 출력 유무·확인 가능한 실행 경계를 함께 제공합니다. 준비 단계와 모델 결과는 같은 실행 ID를 사용하므로 모델 시작 표시만 저장되지 않아도 현재 결과를 조회할 수 있습니다. 세션 종료에서 저장 오류가 반환되면 같은 실행에 오류 결과를 추가하고 부분 출력·원래 종료 원인을 보존하며 사용량은 중복 집계하지 않습니다. 실행 경계가 없는 과거 기록은 기존 결과 우선 조회를 유지하며, 직접 연결한 다른 작업에서는 종료 의도의 결과만 읽습니다. Planner 회차가 실패·취소되면 그 회차가 받은 종료 이벤트를 다음 정상 회차에 다시 전달합니다. 이는 메모리 내 인계 복구이며 서버 재시작을 넘는 이벤트 큐나 Worker 행동의 자동 재실행은 아닙니다.

`report_finding`의 선택 값 `evidence_hint_id`는 생략·null·0을 미지정으로, `traffic_refs: null`은 연결 없음으로 처리합니다. 실제로 지정한 근거 ID·트래픽 항목은 검증하며 잘못된 값을 조용히 받아들이지 않습니다. 지연 도구 실행에서도 같은 nullable 스키마 계약을 적용합니다. 의도·자산·finding·사실 ID의 의미는 단일·배치 도구와 후속 조회에서 일치시킵니다.

핵심 저장 경로는 [`db/graph_mutations.go`](../../db/graph_mutations.go), [`db/asset_observations.go`](../../db/asset_observations.go), [`db/planner_state.go`](../../db/planner_state.go), [`db/worker_result.go`](../../db/worker_result.go)에 있습니다. 호출·상세 조회는 [`agent/tools.go`](../../agent/tools.go), [`agent/planner.go`](../../agent/planner.go), [`agent/worker.go`](../../agent/worker.go)에서 이어집니다. ### 의도 배정과 미완료 인계

원본과 이 포크는 모두 `add_intent.intents`의 각 항목을 별도 의도로 저장하고 Worker 한 실행에 하나를 전달합니다. Planner가 전체 범위를 보고 Worker가 할당된 질문을 깊게 수행하는 구조는 유지합니다.

| 원본 지침·인계의 한계 | 현재 지침 |
| --- | --- |
| 한 문장 탐색 방향에 서로 독립적인 검증 주제를 묶을 수 있음 | 의도마다 하나의 검증 질문 또는 독립 산출물과 종료 조건을 명시. 같은 질문의 준비·정상 대조·입력 변형·재현·실제 영향 확인은 한 Worker에서 이어감 |
| `done`을 이미 다룬 방향으로 보고 재배정에 새로운 기법을 요구 | 정상 반환과 모든 질문의 검증 완료를 구분. 실제 결과·남은 질문·확인 범위를 보고 미완료 검증을 이어가거나 후속 의도로 배정 |
| 같은 부정 방향의 재검증은 최대 한 번, 사실은 기본 한 개로 제한 | 횟수나 사실 개수로 결론을 닫지 않음. 새 근거·반례·재현·정상 대조와 미검증 질문을 기록하고 필요한 검증 지속 |
| 받은 응답은 같은 URL로 다시 요청하지 않도록 안내 | 저장된 응답은 재사용하면서 정상 대조·입력·계정·상태 변화·재현성·오류 복구에 필요한 새 요청은 수행 |
| 예산 종료 결과를 마지막 한 문장으로 요구 | 부분 결과·근거 ID·마지막 진행 지점·파일 참조·남은 질문·재개 조건을 인계. 예산 소진을 완료나 부정 결론으로 해석하지 않음 |

보고 가능한 취약점을 찾았으면 근거와 함께 먼저 기록하되, 같은 질문의 필요한 검증까지 종료한 것으로 간주하지 않습니다. 대상의 HTTP 4xx·5xx나 `Blocked illegal activity` 응답을 도구가 실행 전에 반환한 명시적 거부·가로채기 결과와 구분하고 실패 출처·조건을 기록합니다. 명시된 사용자 범위·도구 차단·취소·시간 제한은 유지합니다. 허용된 검증에 정상 UI의 존재나 사전 삭제 성공 보장 같은 별도 조건을 임의로 덧붙이지 않고, 실제 정리 실패는 대상과 이유·재개 조건으로 남깁니다.

한 회차의 최대 4방향 안내는 전체 탐색 범위의 상한이 아닙니다. 독립 질문을 네 항목에 억지로 합치지 않으며, 미배정 질문과 직렬 의존성은 Todo와 fact/finding 근거로 보존합니다. Todo 상태만으로 실제 Worker가 실행 중이라고 판단하지 않습니다. 남은 질문을 검증할 Worker가 없으면 다음 검증 또는 필요한 선행 조건 확보를 배정하도록 안내합니다. 보고서와 공유 문서는 결과가 모였을 때 정리하며 작성 자체를 목표 달성으로 취급하지 않습니다.

이 지침은 모델의 판단을 돕습니다. 자연어 의도를 코드로 강제 분할하거나 모든 미검증 문장의 후속 실행을 보장하는 장치는 아닙니다. 완료 검사는 저장된 의도·목표·Todo·근거 상태를 검증하며 자유 문장의 의미를 완전히 판정하지 않습니다. 실제 탐색 깊이·발견량·시간당 성능은 같은 조건의 진단 비교로 별도 확인해야 합니다.

Planner·Worker 본문, 도구 설명과 선택 인자 스키마는 저장값이 확인된 배포 기본값과 정확히 일치할 때만 갱신합니다. 사용자 수정·선택한 과거 버전·도구 연결·활성 상태·삭제를 보존하며, 이관 완료 표식을 같은 트랜잭션에 저장해 재시작 중복과 실패 시 부분 적용을 방지합니다. 기본 작업 템플릿도 이름과 설명이 확인된 기본값과 일치할 때 설명만 갱신합니다. 사용자가 편집한 설명·삭제한 템플릿·다른 설정과 이미 생성한 작업은 보존합니다.

역할별 프롬프트는 전역 설정이므로 새 버전이 적용되면 기존 작업의 다음 Planner 회차·새 Worker 실행에도 영향을 줍니다. 본문 버전을 되돌려도 코드가 붙이는 안내는 해당 실행 버전의 내용을 유지합니다. [기본값 갱신 구현](../../server/exploration_restoration_defaults.go), [검증 범위](validation.md#탐색지침과-기본값-검증)
