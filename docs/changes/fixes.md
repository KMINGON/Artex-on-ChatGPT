4종 템플릿의 보완 문구는 새 설치에서 최초 등록하는 기본값입니다. 기존 DB의 사용자 템플릿이나 이미 생성한 작업을 자동 변경하지 않습니다. 일반 검증의 기존 본문과 각 프리셋의 허용 범위·기본 설정값은 유지합니다. 이 템플릿 문구 변경 자체는 목표 개수를 강제하지 않습니다. 활성 의도와 미완료 Todo에 대한 완료 검토는 [그래프·에이전트 인계](#그래프에이전트-인계)에서 설명하며, 문구의 실제 모델 실행 효과는 별도 검증이 필요합니다.

| 원본 개선 | 도구 연결 | 프록시 미지정은 환경변수 프록시를 상속하지 않는 직접 연결 | Bash·WebFetch·WebSearch에 일관 적용. 지정 프록시는 상속된 `NO_PROXY`로 우회하지 않아 기록 경로 유지 |
| 원본 개선 | MCP·Monitor | Unix MCP 프로세스 그룹 종료, Monitor에 실행 환경 전달 | MCP 자식 프로세스 정리와 프록시·CA 환경 일치 개선 |
| 원본 개선 | 구형 SSE MCP | 초기 연결 대기에 취소가 전달되지 않고 긴 줄을 제한 없이 읽을 수 있음 | 초기 핸드셰이크 취소 전파와 이미지 응답을 고려한 읽기 상한 적용 |
| 포크 수정 | 실패 사용량 | 성공 여부와 사용량 수신 여부 분리 | 실패·미완료 응답에 실제 usage가 있으면 누적. 미수신을 확정된 0으로 간주하지 않음 |
| 원본 개선 | 자동 트리거 | 대기 항목과 처리 위치를 같은 DB 트랜잭션에 저장 | 재시작 때 아직 실행하지 않은 항목 복구. 작업 생성 순서와 다른 timeout 및 재활성화 후 timeout 감지 |

취소는 이미 끝난 도구의 효과를 되돌리지 않습니다. 취소를 무시하는 외부 프로그램까지 모두 즉시 정지시킨다는 보장도 아닙니다. 자동 트리거는 **실행 전 대기 상태만 복구**합니다. 이미 실행을 시작한 상태에서 서버가 종료되면 결과 불명으로 남기며, 도구의 중복 실행을 피하기 위해 자동 재실행하지 않습니다. 대화 기록을 확인한 후 사용자가 재시도해야 합니다. 실행 전에 연결 미설정·로그아웃·기록된 한도 차단을 확인하면 대기 항목을 유지하고 연결 복구 후 다시 시도합니다. 원본 작업이 삭제·보관되면 미실행 항목은 취소하며 작업을 복원해도 자동으로 재발행하지 않습니다.

HTTP 200 이후에도 SSE의 `response.failed`·`error`로 요청이 실패할 수 있습니다. 오류 코드·요청 ID·단계·요청 크기를 기록하며, 출력·도구 실행 후 전체 작업을 자동 반복하지 않습니다. `Output too large` 파일 안내 자체가 모델 컨텍스트 초과를 뜻하지는 않습니다. 원본 HTTP 본문·암호화 추론·자격증명은 진단 로그에 넣지 않습니다.

## 그래프·에이전트 인계

자산 그래프와 탐색 그래프의 기존 구조를 유지하면서 기록·연결·후속 조회가 함께 성공하도록 정비했습니다.

| 구분 | 문제 | 현재 동작 |
| --- | --- | --- |
| 원본 개선 | 사실의 `intent_id`를 생략하면 Worker가 만든 결과에 생산 의도 연결이 없고 다른 Worker ID를 넣을 수도 있었음 | 실제 실행 의도로 기본 귀속하고 다른 Worker의 ID는 거부. 사실과 필수 `yields` 연결을 한 트랜잭션에 저장 |
| 원본 개선 | 의도·사실 등록 후 연결 실패를 무시할 수 있었음 | 노드·부모·자산 앵커를 함께 저장하고 실패 시 전체 롤백. 초기 의도와 모델 없는 수동 의도도 같은 등록 경로 사용 |
| 원본 개선 | Planner의 `parent_ids` 안내가 의도 ID를 허용하는 것처럼 보이지만 도구는 fact/finding만 허용 | 기본 지침·도구 스키마를 실제 규칙에 맞춤. 잘못 전달한 의도 ID에는 실제 결과 노드 ID를 안내 |
| 원본 개선 | 목표 증명 이유가 저장되지 않고 연결·상태 갱신 오류를 무시 | 근거 노드·이유·시각과 `proves` 연결·목표 상태를 함께 저장. 동시 증명도 같은 잠금 아래 판정 |

### 의도 배정과 미완료 인계

원본과 이 포크는 모두 `add_intent.intents`의 각 항목을 별도 의도로 저장하고 Worker 한 실행에 하나를 전달합니다. 기존의 “한 문장 탐색 방향”만으로는 서로 독립적인 검증 주제가 한 의도에 섞일 수 있어 기본 지침을 보완했습니다.

| 구분 | 이전 동작 | 현재 지침 |
| --- | --- | --- |
| 원본 개선 | 의도 한 문장에 서로 다른 증거·완료 기준을 가진 주제를 함께 넣을 수 있음 | 하나의 검증 질문 또는 사용자가 요구한 독립 산출물과 종료 조건을 명시. 같은 질문의 정상 대조·입력 변형·관련 자산 비교는 한 Worker가 깊게 수행 |
| 원본 개선 | Worker 정상 반환을 해당 방향 전체를 다룬 것으로 판단하기 쉬움 | 판단에 관련된 종료 의도의 실제 결과와 남은 질문을 확인하고 필요한 후속 의도를 배정한 뒤 목표 판단. 이미 전달된 상세는 재사용하고 부족할 때만 추가 조회 |
| 포크 수정 | 기본 본문은 후속 단서를 summary에, 추가 인계 지침은 detail에 쓰도록 안내 | 의도 안팎의 미검증 질문을 summary에 표시하고 detail에는 확인 범위·남은 대상·근거·차단 원인·재개 조건을 기록 |
| 지침 보완 | 일반 HTTP 실패를 전체 방향의 정책 차단으로 오해할 수 있음 | 502·404·도구 오류와 명시적 가로채기 차단을 구분. 기존 허용 범위와 차단을 지키며 같은 실패를 근거 없이 반복하지 않음 |

한 회차의 최대 4방향 안내는 전체 탐색 범위의 상한이 아닙니다. 서로 독립적인 질문을 네 항목에 억지로 합치지 않으며, 직렬 단계는 기존 Todo와 fact/finding 근거 연결을 사용합니다. 새 후속 큐·필드·완료 상태는 추가하지 않았고, 그래프 저장·취소·재개·완료 검증과 모델 설정은 유지합니다. 이는 모델의 판단 지침이며 넓은 의도를 코드로 거절하거나 모든 미검증 항목의 후속 실행을 보장하는 장치는 아닙니다.

새 버전 시작 시 `a1396fa`의 기본 Planner·Worker 본문과 정확히 일치하는 저장값만 새 프롬프트 버전으로 갱신합니다. `add_intent`도 확인된 이전 기본 설명과 설명 필드만 바꾸며 사용자 편집·도구 연결·활성 상태·기타 스키마는 보존합니다. 기존 한국어화가 인식하는 옛 기본값은 그 이관을 먼저 거칩니다. 사용자 수정·미확인 이전 본문, 작업 템플릿과 기존 작업의 설명·목표·제약은 자동 교체하지 않습니다.

갱신 완료 표식은 같은 트랜잭션에 저장하므로 재시작 때 버전을 반복 추가하지 않으며, 이후 사용자가 이전 본문 버전을 다시 선택해도 재덮어쓰지 않습니다. 역할별 프롬프트는 전역 설정이므로 새 버전이 적용되면 기존 작업의 다음 Planner 회차·새 Worker 실행에도 영향을 줍니다. 본문 버전을 되돌려도 코드가 붙이는 안내는 해당 실행 버전의 내용을 유지합니다.
