# 브라우저·인증 세션과 실행 설정

원본 ARTEX에도 브라우저 MCP와 작업 템플릿이 있었습니다. 현재 버전은 Chromium 실행 환경, 같은 세션의 수동 인증, 실제 이미지 전달과 설정 저장을 보완합니다. 작업 템플릿은 입력값을 채우고, 시스템 설정과 작업 목록에서 병렬 실행 수를 조정합니다. [전체 변경점](changes.md) · [설치](../README.md#빠른-시작)

## 브라우저 사용

새 설치는 기본 `browser` MCP를 활성화해 Worker와 침투 테스트 채팅에 연결합니다. 기존에 비활성화했거나 명령·인자를 바꾼 경우 그 설정을 유지합니다. 다시 사용하려면 MCP 설정에서 활성화하세요. 사용자 지정 브라우저 MCP는 아래 관리 화면과 연결되지 않을 수 있습니다.

브라우저는 에이전트가 도구를 호출할 때 시작합니다. 별도의 브라우저 우선 검증 단계는 없으며, HTTP·파일·브라우저 등 어떤 도구를 사용할지는 원래 에이전트 흐름에서 결정합니다. 브라우저 응답을 자동으로 그래프 관찰 노드로 등록하는 경로도 없습니다. 에이전트는 받은 결과에서 필요한 사실·발견을 기존 그래프 도구로 기록합니다.

### 같은 세션에서 로그인하기

1. 에이전트가 페이지를 열고 사용자 인증이 필요하면 `browser_request_user`로 조작을 요청합니다.
2. **브라우저 세션**에서 대기 중인 세션을 열고 주소·탭·화면을 확인합니다. 클릭·드래그·키 입력·스크롤로 조작할 수 있습니다.
3. 대상 페이지에서 직접 로그인한 뒤 제어를 반환하면 에이전트가 같은 페이지에서 작업을 이어갑니다.

사용자 조작 중에는 해당 세션의 에이전트 조작이 대기합니다. 인증 대기는 작업의 전체 시간 제한을 멈추지 않으며, 제어 반환 자체가 사이트의 로그인 성공을 뜻하지는 않습니다. 화면은 캡처 이미지 갱신 방식입니다.

대기 중 세션 종료·삭제·프로세스 종료·작업 취소는 오류로 전달합니다. 다음 인증 대기에 이전 대기의 늦은 응답을 적용하지 않습니다. CAPTCHA 등 추가 인증은 사용자가 같은 화면에서 처리하는 방식이며 자동 해결 기능은 아닙니다.

### 세션과 저장 범위

작업·의도·대화별 프로필을 분리하고, 전역 브라우저 상한에 도달하면 빈자리를 기다립니다. 실행 종료·취소 시 프로세스를 정리하고 같은 세션을 재개할 때 쿠키·localStorage·sessionStorage를 복원합니다. 메모리 상태나 열려 있던 모든 탭을 그대로 복구하지는 않으며 서버 재시작이 에이전트 작업의 자동 재개를 뜻하지도 않습니다.

같은 작업이라도 서로 다른 의도는 별도 프로필을 사용합니다. 앞선 의도의 로그인 쿠키를 다음 Worker에 자동으로 복사하지 않습니다. 프로필은 Compose의 `artex-auth` 볼륨에 보관하며 일반 작업 파일 목록에 표시하지 않습니다. 유휴 세션을 삭제하면 프로필과 인증 정보도 삭제하고, 작업·대화 삭제 시 연결된 프로필을 정리합니다.

## 이미지와 JavaScript

MCP 스크린샷과 이미지 파일 `Read`는 모델에 실제 이미지로 전달합니다. 텍스트와 이미지가 섞인 도구 결과도 보존하며, 파일·해시를 저장해 대화 재개 시 다시 읽습니다. 일반 로그와 대화 JSON에 이미지 base64를 중복 기록하지 않습니다.

| 범위 | 현재 처리 |
| --- | --- |
| 형식 | PNG·JPEG·비애니메이션 GIF·WebP |
| 도구 결과 | 이미지당 최대 8MiB, 결과당 최대 4개 |
| 모델 요청 | 최근 이미지 최대 8개, 인코딩된 이미지 합계 최대 32MiB |
| 예산 초과·누락 파일 | 설명·파일 참조·다시 읽기 안내로 대체 |
| 입력 경로 | MCP 이미지 결과와 이미지 파일 `Read` |

이미지 파일을 삭제하면 해당 시각 정보를 복원할 수 없습니다. 오래되거나 누락된 이미지는 잘못된 이미지 요청으로 전체 호출을 실패시키는 대신 참조로 남깁니다. 별도의 채팅 이미지 업로더나 OpenAI 호스팅 도구는 추가하지 않습니다.

기본 `api-recon` 스킬은 설치된 Playwright를 사용해 JavaScript·fetch/XHR·WebSocket 등을 관찰합니다. `forward`를 지정하지 않으면 실제 API 요청을 전송한 뒤 클라이언트 응답을 모의 수정하므로 읽기 전용 수집은 아닙니다. 모의 응답은 프런트엔드 경로 발견의 근거이며 실제 인증 성공이나 취약점 입증과 구분합니다. 관리 브라우저의 정상 요청을 일괄 모의 응답으로 바꾸지는 않습니다.

## 작업 템플릿

원본의 설명·목표·분류·허용/차단 규칙에 작업 이름과 고급 설정의 저장을 추가했습니다. **새 작업 → 작업 템플릿**에서 기본 템플릿이나 사용자가 저장한 템플릿을 선택합니다.

기본 템플릿은 **실습 · 전체 검증, 운영 · 관찰, 운영 · 일반 검증, 운영 · 확장 검증** 4종입니다. 각 설명은 대상·허용 범위·검증·결과 정리를 담은 6줄과 목표 1문장이며, 작업 이름·시간 제한·계획 주기·초기 의도 생성·커버리지 값은 지정하지 않아 현재 폼 값을 유지합니다.

`실습 · 전체 검증`의 목표는 취약점 재현·영향 정리와 함께, 완료 판단 전에 기존 기록과 자산·공격 표면을 대조하여 누락·미검증 영역과 새로운 탐색 경로를 확인하도록 안내합니다. 이미 검증한 경로의 반복보다 미탐색 영역의 검증을 우선하며, 추가 탐색에서 새 항목이 나오지 않거나 설정된 예산에 도달하면 미검증 사항과 종료 사유를 남기고 목표 달성 여부는 실제 근거로 판단합니다.

1. 템플릿을 선택하면 저장된 이름·분류·설명·목표·규칙·고급값이 기존 입력란에 채워집니다.
2. 대상 주소와 계정·자료 안내 등을 편집합니다. 이미 작성한 값을 바꾸는 경우 기존 적용 확인창에서 확인합니다.
3. 생성하면 화면의 최종값을 기존 작업 생성 API에 전달합니다. 목표 분해·계획·Worker 실행에 별도 템플릿 파이프라인을 추가하지 않습니다.

템플릿의 목록 이름과 새 작업에 넣을 **작업 이름**은 별개입니다. 시간 제한·계획 주기·초기 의도 생성·커버리지 설정도 저장할 수 있습니다. 옛 템플릿에 없는 값이나 **현재 값 유지**로 저장한 항목은 폼 값을 유지하며, 미지정·0·false와 초 단위 시간을 구분합니다. 모델·연결 작업·회사 선택은 템플릿으로 변경하지 않습니다.

기본 템플릿은 등록 이력이 없는 환경에 한 번만 추가하며, 같은 이름의 사용자 템플릿을 덮어쓰지 않습니다. 기존 등록 이력이 있으면 삭제된 기본값을 다시 만들지 않습니다. 템플릿 수정·삭제는 이미 만든 작업을 바꾸지 않습니다. 과거에 자동 등록한 것으로 식별되고 필드와 본문이 그대로인 템플릿만 정리하며, 사용자 수정·직접 작성 템플릿은 보존합니다. 구형 정책 필드는 원문 JSON을 보존하고 설명·기존 동작 제약으로 한 번 이관합니다. [이관 범위](changes/operations.md#기존-설정의-이관)

## 자원 설정

**시스템 설정**의 상세 카드에서 새 작업의 Worker 수와 동시 브라우저 상한을 각각 조정합니다. 동시 작업 상한은 **작업 목록 → 동시 실행 설정**에서 조정합니다.

기본값은 **Worker 3, 동시 작업 제한 없음, 브라우저 4**입니다. 기존에 저장한 수치는 유지합니다.

Worker 수는 작업 생성 시 저장하므로 기존 작업의 Worker 수는 유지됩니다. 동시 작업·브라우저 상한은 서버 전체 설정입니다. 상한을 낮추어도 이미 실행 중인 브라우저를 강제 종료하지 않고 이후 실행을 조정합니다.

## 프록시와 Docker

트래픽 기록은 ARTEX 내장 프록시를 사용합니다. Docker 이미지에는 Chromium·Playwright·시스템 라이브러리·NSS 인증서 도구가 포함되고, Compose는 `init`과 1GiB 공유 메모리를 설정합니다. 호스트 설치에서는 브라우저 실행 의존성을 별도로 준비합니다.

관리 브라우저는 기록 프록시 CA를 자체 인증서 저장소에 등록합니다. HTTPS 오류를 일괄 무시하지 않으며 사용자가 정한 외부 프록시 경로를 유지합니다. WebFetch가 기록 프록시 장애를 확인하면 한 번 기록 경로를 우회하고 결과에 미기록을 표시합니다. 이때도 명시한 외부 프록시는 유지합니다.

원본부터 기록 프록시는 대상 서버 인증서를 엄격하게 검증하지 않는 연결 설정을 사용합니다. 브라우저의 프록시 CA 신뢰와 대상 인증서의 유효성은 구분해야 합니다. SSE·큰 응답은 끝까지 버퍼링하지 않으며 본문 생략·완료 불명 상태를 표시합니다. 프록시의 HTTP 기록과 api-recon의 CDP WebSocket 프레임 수집은 별도 경로입니다.

대상 주소는 [README 접속 주소](../README.md#접속-주소), 증거 연결은 [트래픽 증거](finding-traffic-evidence.md)를 참고하세요.

## 언어

화면은 한국어·영어를 지원하며 새 설치는 한국어로 시작합니다. 기존 다른 언어 선택값은 한국어로 정규화합니다. 선택한 언어의 에이전트 출력 지시를 사용하지만 사용자 프롬프트·과거 대화·대상 사이트·도구 출력은 자동 번역하지 않습니다.
