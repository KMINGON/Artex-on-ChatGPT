| 영역 | 원본 또는 이전 동작 | 이 포크의 변경 |

| 첫 모델 설정 | 저장·연결 테스트 뒤 별도 활성화를 놓치면 작업이 `model_error`로 실패 | 기존 기본 모델·환경 모델이 없으면 첫 사용 가능한 프로필을 기본으로 지정. 실행할 모델이 없으면 작업을 대기시키고 설정 안내 |
| 대화에서 만든 작업 | 대화에서 선택한 모델을 생략하고 전역 기본 모델로 실행 | 명시한 작업 모델·상위 작업 모델이 없으면 대화에서 선택한 프로필을 새 작업에 전달 |
| 설정 변경 중 동시 요청 | 무효화한 예전 ChatAgent가 캐시에 다시 들어올 수 있음 | 캐시 세대 확인과 프로필 적용 동기화. 설정 적용 완료 후 새 실행부터 반영하며, 이미 진행 중인 요청은 유지 |
| 구독 한도 | 같은 연결의 신규 요청이 계속 발생할 수 있음 | 한도 오류를 해당 **연결 등록 단위**로 보관하고 신규 추론 중지. 사용자가 **한도 재확인**을 실행해 성공하면 해제 |
| 계정 표시 | 같은 이메일의 여러 연결이 구별되지 않음 | 연결별 식별 라벨 표시. 이메일이 같아도 인증·한도 상태를 합치지 않음 |
| 모델·추론 강도 | 모델 목록과 기능 호환성이 혼재 | 공식 문서로 확인된 API 모델의 설정 검사. 구독·미확인 모델의 기존 설정은 보존하고 OpenAI 응답으로 검증 |
| 도구 승인 Judge | `temperature=0`이 기본 추론 설정과 충돌할 수 있음 | 불필요한 temperature 지정을 제거. 지원하지 않는 `reasoning=none`을 강제하지 않음 |

**기존 OpenAI API에서도 일반 압축은 동작했습니다.** 이번 개선은 “컨텍스트 관리 전체가 Claude에서만 가능했다”는 뜻이 아닙니다. 누락되던 OpenAI 응답 상태를 보존하고, 공통 실행 엔진의 압축·저장 결함을 보완한 것입니다. 메시지를 편집·압축하면 원형 상태를 그대로 재사용할 수 없어 해당 opaque 상태를 제거합니다.

설정 저장 후 적용 과정에서 DB 확인에 실패하면 HTTP 503을 반환하고 이전 연결로 새 요청을 실행하지 않습니다. DB 연결을 복구한 뒤 프로필을 다시 저장하거나 활성화하세요.

작업·계획·Worker, Bash 등 로컬 도구, MCP, Skills, 기존 검색 연동은 유지합니다. DeepSeek 전용 검색 경로는 제거했습니다. Norma는 런타임에 원본을 다운로드하지 않으며, [로컬 replace](../go.mod)가 지정하는 [`third_party/norma`](../third_party/norma/ARTEX_PATCHES.md)를 함께 빌드합니다.

## 한국어화

화면의 고정 라벨에 더해 **ARTEX가 기본 제공하거나 실행 중 생성하는 중국어 안내**를 한국어로 바꿨습니다.

| 범위 | 반영 내용 | 유지한 동작 |
| --- | --- | --- |
| 에이전트 | 기본 시스템 프롬프트, 변수 설명·예시, 보고서·재검증 지침, 작업·마무리 안내 | 역할, 작업 순서, 권한 범위, 템플릿 변수와 도구 호출 조건 |
| 도구 | ARTEX 도구 설명·인자 안내·오류·결과, Norma 대화형 셸·백그라운드 작업 알림 | 도구 이름·인자 키·자료형·필수값·enum·기본 인자와 실행 로직 |
| 가로채기 | 명령 규칙 20개·자산 규칙 4개의 표시 문구, Judge 정책·판정 사유, 승인·차단 안내 | 정규식·도메인·우선순위·활성 상태·시간 제한. 새 한국어 판정과 기존 중국어 판정 형식을 함께 검증 |
| 실행 화면 | 트리거 제목·컨텍스트, 첨부·인용 안내, 상태·오류·로그, 보조 질문 지침 | 기존 상태값·기록 형식. 한국어 로그 오류 분류 및 이전 인용 토큰 호환 |
| 기본 스킬 | `api-recon`, `scopesentry` 문서·예시 | 명령·프로토콜·응답 매칭 패턴과 파일 구조 |

기존 DB에는 확인된 이전 기본값과 **정확히 일치하는 부분만** 적용합니다. 도구는 설명 필드별로 비교하고, 프롬프트는 본문 전체를 비교해 새 버전을 추가합니다. 사용자 편집·도구 연결·비활성화·삭제한 규칙은 보존하며, 앞서 실행되던 기본값 강제 갱신에도 사용자 편집 보호를 추가했습니다. 새 설치는 한국어 기본값으로 시작합니다.

직접 수정한 본문, 확인되지 않은 더 오래된 기본값, 과거 대화·감사 기록·프롬프트 이력, 대상 사이트 응답과 외부 도구 출력은 일괄 번역하지 않습니다. 기존 사용자 프롬프트에 중국어 답변 지시가 남아 있다면 직접 수정하거나 에이전트 설정의 기본값 복원을 사용하세요. 도구의 기본값 복원은 연결·활성 상태도 초기화하므로 필요한 설명만 편집할 수도 있습니다.

번역 후에도 작은 컨텍스트 창에서 보조 질문 요약이 동작하도록, 실제 조립된 요청의 길이를 확인해 요약 조각 크기를 조정합니다. 스키마·템플릿·판정 파서·기존 DB 갱신은 회귀 검사로 확인합니다.

소스의 `github.com/Autumn-27/artex`는 현재 프로젝트의 **Go 모듈 이름**이고, Norma도 로컬 사본으로 빌드합니다. 원본 저장소에서 실행 코드를 받아오는 경로가 아닙니다. 업데이트 다운로드는 `KMINGON/Artex-on-ChatGPT`를 사용하며, 원본 링크·저작권·라이선스 고지는 출처 기록으로 유지합니다.

## 기억·실행 안정성

| 개선 | 바뀐 동작 | 확인한 효과 |
| --- | --- | --- |
| 압축 경계 | 도구 호출과 결과를 한 묶음으로 취급 | 압축 경계에 걸린 도구 결과가 요약과 다음 요청 양쪽에서 빠지는 경우 방지 |
| 압축 시점 | 이전 usage뿐 아니라 현재 메시지·새 도구 결과·시스템/도구 정의의 추정 크기도 반영 | 오래된 토큰 수 때문에 큰 결과를 받은 뒤에도 압축하지 않던 경우 보완 |
| 압축 기록 | 시작·부분·완료 레코드의 버전·개수·해시 검증 | 완성되지 않은 체크포인트를 완성된 대화로 채택하지 않음 |
| 재개·쓰기 실패 | 손상 이력, 쓰기·동기화 실패를 `storage_error`로 전달 | 빈 기억으로 조용히 계속하거나 기록에 실패한 실행을 성공으로 표시하지 않음 |
| 출력 상한 | 이어쓰기 예산이 소진되면 `output_limit` | 부분 출력과 미완료 이유를 표시. Worker는 `exhausted`, 저장 오류는 `blocked`로 분류 |
| 도구 취소 | 동시 실행 슬롯을 기다리는 도구도 취소 확인 | 종료 이벤트 이후 대기 도구가 새로 시작하는 경우 차단 |
| 긴 도구 결과 | 본문 속 저장 표식과 무관하게 최종 크기 검사 | 표식 문자열만으로 길이 제한을 우회하지 않음. 전체 결과 파일과 참조 유지 |
| 작업 개요 | 현재 작업의 목표·힌트·요약과 압축 요약에 텍스트 예산 적용 | `graph_overview`와 Planner의 사전 주입 개요가 함께 제한됨. 생략 여부·원문 조회 방법을 표시하고 저장된 원문·Planner의 원래 작업 목표는 보존 |
| 웹 본문 수신 | 중간 끊김·시간 초과를 도구 오류로 전달하고 2MiB 수신 상한의 잘림을 표시 | 일부 응답을 전체 성공으로 오인하지 않음. 기존 출력 50,000바이트 제한은 UTF-8 문자 경계를 지켜 적용 |
| 도구 연결 | 프록시 미지정은 환경변수 프록시를 상속하지 않는 직접 연결 | Bash·WebFetch·WebSearch에 일관 적용. 지정 프록시는 상속된 `NO_PROXY`로 우회하지 않아 기록 경로 유지 |
| MCP·Monitor | Unix MCP 프로세스 그룹 종료, Monitor에 실행 환경 전달 | MCP 자식 프로세스 정리와 프록시·CA 환경 일치 개선 |
| 실패 사용량 | 성공 여부와 사용량 수신 여부 분리 | 실패·미완료 응답에 실제 usage가 있으면 누적. 미수신을 확정된 0으로 간주하지 않음 |
| 자동 트리거 | 대기 항목과 처리 위치를 같은 DB 트랜잭션에 저장 | 재시작 때 아직 실행하지 않은 항목 복구. 작업 생성 순서와 다른 timeout 및 재활성화 후 timeout 감지 |
| 검사·배포 | 루트와 Norma를 별도로 검사, 원본 이미지 자동 사용 제거 | 별도 Go 모듈의 회귀를 확인하고 원본 앱을 이 포크로 오인해 실행하는 경로 차단 |

취소는 이미 끝난 도구의 효과를 되돌리지 않습니다. 취소를 무시하는 외부 프로그램까지 모두 즉시 정지시킨다는 보장도 아닙니다. 자동 트리거는 **실행 전 대기 상태만 복구**합니다. 이미 실행을 시작한 상태에서 서버가 종료되면 결과 불명으로 남기며, 도구의 중복 실행을 피하기 위해 자동 재실행하지 않습니다. 대화 기록을 확인한 후 사용자가 재시도해야 합니다. 실행 전에 연결 미설정·로그아웃·기록된 한도 차단을 확인하면 대기 항목을 유지하고 연결 복구 후 다시 시도합니다. 원본 작업이 삭제·보관되면 미실행 항목은 취소하며 작업을 복원해도 자동으로 재발행하지 않습니다.

HTTP 200 이후에도 SSE의 `response.failed`·`error`로 요청이 실패할 수 있습니다. 오류 코드·요청 ID·단계·요청 크기를 기록하며, 출력·도구 실행 후 전체 작업을 자동 반복하지 않습니다. `Output too large` 파일 안내 자체가 모델 컨텍스트 초과를 뜻하지는 않습니다. 원본 HTTP 본문·암호화 추론·자격증명은 진단 로그에 넣지 않습니다.

## Noa·원본 잔재 정리

실험적 Noa의 설정 화면·설정 API·에이전트 연결·`noa`/`noaadapter` 패키지를 제거했습니다. 채팅·계획자·작업자·메인 에이전트는 기존 **기본 자동 압축**을 사용합니다. 오래된 도구 결과 정리, 대화 요약과 최근 메시지 보존, 문맥 초과 후 복구 및 별도의 탐색 그래프 요약은 유지합니다.

기존 DB의 `noa_compaction` 값은 더 이상 읽지 않습니다. 예전 Noa 아카이브·대화 원문을 자동 삭제하지 않으며, Noa 요약 상태는 더 이상 적용하지 않습니다. 예전 Noa 세션은 저장된 대화 이력에서 기본 압축으로 재개하므로 첫 재개에 재요약이 발생할 수 있습니다.

| 정리한 항목 | 이유·유지한 대안 |
| --- | --- |
| `detections/`와 방어 안내 | 앱 실행에서 사용하지 않는 별도 Sigma·Suricata·탐지 자료와 전용 테스트 제거. 앱의 명령·자산 가로채기와 감사 기록은 유지 |
| 원본 다국어·실험 문서 | 중복 문서, 과거 모델 비교 결과·벤치마크 기록 제거. 현재 한국어 [트래픽 증거 안내](finding-traffic-evidence.md)와 [보조 질문 설명](../sidequestion/README.md)은 유지 |
| 과거 설치·클라우드·벤치 스크립트 | Compose와 중복되거나 현재 구성에서 동작하지 않는 경로 제거. `build.sh`, `dev.sh`, 시작 스크립트와 비밀번호 복구 도구는 유지 |
| GitHub 워크플로 | 자동·수동 CI 및 기존 릴리스 정의 제거. 검증은 로컬 명령과 [Compose 검사](../scripts/test-compose.py)로 실행 |
| 프런트엔드 초기 템플릿 | 사용하지 않는 초기 번역 추출기·비활성 프록시·데모 이미지 제거. 현재 번역 키 검사와 테마 생성기는 유지 |

라이선스·저작권·출처 고지와 실행에 사용하는 기본 스킬은 정리 대상에서 제외합니다. 개인 조사·검증 자료는 계속 Git에서 제외된 `reference/`에 보관합니다.

## Daybreak 선택

공식 문서 확인일: **2026-10-21**. 모델과 접근 프로그램은 별도 값입니다. `-latest` 별칭이 폐지되었다고 해석하지 않으며, 기존 모델을 자동으로 다른 모델로 바꾸지 않습니다.

### OpenAI API 키

**시스템 → LLM → API 프로필**에서 모델과 **API 액세스 프로그램**을 각각 설정합니다.

| 선택 | 요청에 보내는 값 | 의미 |
| --- | --- | --- |
| 기본값 (필드 생략) | 필드 생략 | 모델·조직·프로젝트 권한에 따라 서버가 결정. **Daybreak 끄기와 다름** |
| `standard` (Standard) | `access_programs.cyber=standard` | 지원 모델에서 표준 보호 설정 명시 |
| `daybreak_blue` (Daybreak Blue) | `access_programs.cyber=daybreak_blue` | 해당 모델·프로젝트의 승인 필요 |
| `daybreak_red` (Daybreak Red) | `access_programs.cyber=daybreak_red` | 해당 cyber 모델과 별도 Red 승인 필요 |

`gpt-6-sol`의 Daybreak 값은 Blue입니다. `gpt-6.1-sol`·`gpt-6-astra`도 요청값은 Blue지만 조직의 **Red 승인과 프로젝트 접근 설정**이 필요하며, Red 값을 보내면 안 됩니다. `gpt-5.6-cyber`는 Red를 사용합니다. 토글만으로 권한이 생기지 않습니다. [공식 Daybreak 안내](https://developers.openai.com/api/docs/guides/daybreak)

지원하지 않는 조합이나 권한 오류는 그대로 알립니다. ARTEX가 다른 모델·프로그램·과금 방식으로 바꾸어 성공처럼 처리하지 않습니다. 연결 테스트에는 서버가 반환한 실제 모델과 접근 프로그램을 표시하며, 사용량 기록에도 해당 메타데이터를 보존합니다. 응답에 값이 없으면 요청 설정만으로 실제 적용을 단정하지 않습니다. [Responses API 요청 규약](https://developers.openai.com/api/reference/resources/responses/methods/create)

### ChatGPT 구독

**연결한 계정의 모델 목록을 새로고침하고, 그 목록에서 모델을 선택**합니다. 목록에 Daybreak 모델 ID 또는 별칭이 제공된다면 ID를 그대로 요청할 수 있습니다. 다른 계정의 목록이나 API의 모델 목록을 구독 계정의 권한으로 간주하지 않습니다. [구독 모델·추론 안내](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

현재 공개 SIWC 문서에서는 구독 요청에 `access_programs.cyber`를 명시하는 계약을 확인하지 못했습니다. 따라서 이번 버전은 **구독의 명시적 프로그램 설정을 전송하지 않고**, 해당 값이 있는 설정은 로컬에서 오류로 안내합니다. 이는 ChatGPT 전체에서 Daybreak를 쓸 수 없다는 뜻이 아닙니다. 구독 경로의 제공 모델·응답에 실제로 나타난 정보를 기준으로 처리합니다. API나 Codex의 계약을 이 경로에 임의로 적용하지 않습니다.

구독 Daybreak ID 전달과 실제 응답 메타데이터 표시는 모의 요청으로 검사했습니다. 사용자의 계정에서 어떤 모델·프로그램을 실제 사용할 수 있는지는 유효한 계정과 승인 상태로 연결 테스트를 해야 확정됩니다. **이번 작업에서는 실제 계정 추론을 호출하지 않았습니다.**

## API와 구독의 차이

| 항목 | OpenAI API 키 | ChatGPT 구독 |
| --- | --- | --- |
| 사용량·과금 | API 프로젝트의 과금·한도 | 연결한 ChatGPT 계정의 요금제·앱 사용 한도 |
| `temperature` | 내부 호출에서 지원 조건에 맞는 경우 전달. Judge는 강제값 제거 | 전송하지 않음 |
| `max_output_tokens` | 서버 출력 상한 전달 | 전송하지 않음. 보조 요청에 간결한 출력 지시·로컬 시간/수신량 제한 적용 |
| 추론 강도 | 알려진 API 모델의 지원값 검사 | 제공 모델·서버의 지원값 기준. 기본값 생략과 `none`은 서로 다름 |
| Daybreak | 프로그램을 명시하거나 서버 기본값 사용 | 계정 모델 목록의 ID 선택. 명시 프로그램 필드는 ARTEX에서 미검증으로 제한 |
| 도구·입력 | 텍스트·로컬 function·MCP | 동일. 이 포크는 이미지/파일 직접 입력과 OpenAI 호스팅 도구를 구현하지 않음 |
| 응답 상태 | reasoning·`phase`·항목 순서를 완료 응답에서 보존 | 동일한 어댑터·저장 형식 |
| 실패·전환 | 명시적으로 설정한 API 프로필 전환 정책 유지. 원형 상태가 있으면 다른 연결로 자동 재전송 차단 | 유료 API 키 경로로 자동 전환하지 않음 |

구독의 로컬 제한은 서버의 생성 토큰·추론 비용 상한을 대체하지 않습니다. 도구가 없고 호출자가 추론 비활성화와 출력 토큰 수를 요청하는 보조 호출에만 90초와 8–64KiB 수신 제한을 적용합니다. 무작위성 제어나 추론 완전 비활성화를 복원하는 기능이 아닙니다. [SIWC 미리보기 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

한도 오류 후에는 ChatGPT Usage 설정을 확인하고 ARTEX의 **한도 재확인**을 사용합니다. 한 번의 실제 추론을 허용하는 검사로 사용량이 발생할 수 있으며, 성공해야 신규 요청을 다시 허용합니다. 재시작·토큰 갱신만으로 한도가 풀렸다고 간주하지 않고, 계정의 전체 잔량이나 리셋 시간을 추정하지 않습니다. [오류·복구 안내](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)

## 업데이트·데이터 보존

- 기본 실행 경로는 **개인 PC의 Linux·WSL에서 Docker Compose로 앱과 PostgreSQL을 함께 실행**하는 방식입니다. `docker compose up -d`는 이미지가 없으면 현재 소스로 빌드하며, 소스 업데이트 후에는 `docker compose up -d --build`로 다시 빌드합니다. Go·Node.js는 이미지 빌드에서 준비합니다. 호스트 설치 방식도 유지합니다. [실행 안내](../README.md#빠른-시작)
- Compose는 웹을 `${ARTEX_BIND_IP:-0.0.0.0}:${ARTEX_PORT:-8787}`에 게시하고 DB 포트는 호스트에 열지 않습니다. `ARTEX_BIND_IP=127.0.0.1`이면 실행 PC에서만 접속합니다. 트래픽 프록시의 기본 리스너는 컨테이너 내부 `127.0.0.1:8788`입니다. Bash·로컬 도구는 컨테이너 안에서 실행되며 기존 호스트 파일·설정은 자동으로 이관하지 않습니다.
- `host.docker.internal`을 Docker 호스트 게이트웨이에 매핑합니다. 다른 컨테이너는 같은 Docker 엔진·네트워크에서 컨테이너 이름과 내부 포트로 접근합니다. 웹 공개 주소와 에이전트의 대상 주소는 별개이며, Docker 안의 `127.0.0.1`은 ARTEX 자신입니다. [접속 주소](../README.md#접속-주소)
- `.env` 없이도 실행할 수 있습니다. 관리자 초기값은 `ARTEX` / `artex1234`, 새 DB의 사용자·이름은 `artex`, 비밀번호는 `artex-local-db`, 기본 언어는 `ko`입니다. `ARTEX_ADMIN_PASSWORD`는 관리자 비밀번호가 없는 DB에만 적용됩니다. 기존 비밀번호는 `.env` 수정이나 컨테이너 재생성으로 초기화되지 않으며, 기존 PostgreSQL 볼륨의 접속 정보도 유지해야 합니다. 기본 관리자 비밀번호는 로컬 실행용입니다.
- 업데이트 전 앱을 종료하고 DB·앱 파일·인증 저장소를 백업하세요. Compose는 `pgdata`(DB), `artex-data`(`/app/data`), `artex-auth`(`/app/auth`)를 보존합니다. `docker compose stop` 뒤 `up -d`로 재실행하며, `down`은 볼륨을 보존하지만 **`down -v`는 세 볼륨의 데이터를 삭제**합니다. 같은 Compose 프로젝트의 기존 `pgdata`는 유지하고, 다른 호스트 DB·`data/`·인증 폴더는 자동 이관하지 않습니다.
- 앱 시작 시 프로필의 접근 프로그램, 사용량 수신 여부, 트리거 대기/timeout 기록을 DB에 추가합니다. 기존 프로필·작업·대화는 삭제하지 않습니다.
- 새 체크포인트는 완성된 묶음만 읽습니다. 알려진 미완성 묶음은 원본 JSONL을 보존하고 `.recovered` 파생 파일로 재개합니다. 마지막 정상 체크포인트 뒤에 저장된 실제 메시지도 보존합니다. 일반 손상이나 알 수 없는 형식은 임의 복구하지 않고 중지합니다. 기록 동기화로 디스크 I/O는 늘어나며, 원격 모델의 응답 속도가 빨라지는 변경은 아닙니다.
- 옛 체크포인트에는 완료 메타데이터가 없어 일부 저장인지 확정할 수 없는 경우가 있습니다. 새 형식으로 실행한 세션을 구버전 바이너리로 계속 쓰거나 두 버전으로 동시에 쓰지 마세요. 롤백은 백업한 DB·파일과 대응하는 버전을 함께 사용해야 합니다. [Norma 저장 형식 변경](../third_party/norma/ARTEX_PATCHES.md)
- 계정·API 키·모델·**명시적 접근 프로그램**의 변경을 관측하면 새 컨텍스트를 시작합니다. 이전 파일·작업은 보존하지만 모델의 대화 기억은 이어지지 않습니다. 프로그램을 설정하지 않은 기존 프로필의 연결 ID는 유지합니다. 별칭 뒤의 서버 모델 변경까지 로컬 설정만으로 미리 알아내지는 못합니다.
- OAuth 자격증명은 PostgreSQL이나 브라우저에 저장하지 않습니다. Compose에서는 `XDG_CONFIG_HOME=/app/auth` 아래 `/app/auth/artex-on-chatgpt/`를 사용하며 관리자 세션 서명 키도 `artex-auth` 볼륨에 보관합니다. 호스트 설치의 기본 경로는 `~/.config/artex-on-chatgpt/`입니다. OAuth 저장소 권한은 폴더 `0700`·파일 `0600`입니다. 연결 해제와 서버 재시작은 다른 동작입니다.
- Compose의 OAuth 콜백은 별도 임시 포트 대신 공유 웹 포트의 `http://127.0.0.1:${ARTEX_PORT}/auth/callback`을 사용합니다. 브라우저는 Docker를 실행한 같은 PC에서 사용합니다. 관리자 로그인 뒤의 ChatGPT 계정 연결·모델 프로필 저장·활성화 절차는 그대로입니다.
- 멀티모달 입력, OpenAI 서버 압축과 모델 자동 업그레이드는 이번 범위에 포함하지 않습니다.

## 검증 범위

회귀 검사는 모의 OpenAI SSE, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. 실제 API 키·ChatGPT 계정·운영 DB는 사용하지 않습니다.

| 검증 | 범위 |
| --- | --- |
| Responses·Daybreak | API 요청 필드·잘못된 조합·생략, 구독 모델 ID 전달, 실제 응답 모델/프로그램 메타데이터 |
| 계정·프로필 | 한도 차단·재시작·연결별 분리·한 번의 재확인, 키 없는 활성화 거부, 캐시 변경 경합 |
| 문맥·파일 | 도구 교환 압축, 큰 도구 결과, 체크포인트 중단·복구·반복 재개, 쓰기/동기화 실패 |
| 실행·사용량 | 취소 뒤 대기 도구 차단, MCP 정리·Monitor 환경, 출력 미완료, 실패 usage·미수신·실제 0 구분 |
| 트리거 | 저장 실패 시 cursor 미진행, 재개 후 pending 보존, 동시 claim 중복 방지, 병합·역순 timeout·재활성화 |
| 한국어화 | 기본 도구 51개의 스키마 구조 보존, 템플릿·서식 인자 보존, 한국어/기존 판정·인용 형식 호환, 실제 DB에서 사용자 편집·활성 상태·버전 이력 보존 |
| 앱 | Go·웹 테스트/빌드, 별도 Norma 모듈 검사, 격리 DB 통합 검사 |
| Compose | 이미지 없는 첫 실행의 소스 빌드·DB 초기화, 기본 관리자 로그인·내장 웹, 컨테이너 재생성 뒤 비밀번호·파일·JWT·계정 저장소 식별자 보존 |
| 네트워크·첫 실행 | 웹 공개 기본값과 루프백 재설정, Docker 호스트 매핑, 프록시 환경변수 격리, 첫 유효 프로필 활성화와 기존 선택 보존, 대화 모델의 작업 상속 |

Noa 제거 후 Norma 전체 **14개 패키지**와 주요 실행·압축·저장 경로의 race 검사를 통과했습니다. 웹 테스트 **28개**, Node 테스트 **8개**, 5개 언어의 **2,991개 번역 키** 일치도 확인했습니다. 사용하지 않는 아이콘 컴포넌트와 전용 테스트를 함께 삭제하여 웹 테스트 수는 이전 29개에서 28개가 되었습니다.

루트 Go **19개 패키지**를 패키지별 빈 PostgreSQL DB에서 검사하고, Docker 소스 빌드와 [Compose 검사](../scripts/test-compose.py)를 통과했습니다. 앱 초기화·관리자 로그인·한국어 기본값·인증 경계·재생성 후 데이터 보존을 확인했습니다. Noa 패키지와 해당 전용 검사는 제거했으며, 현재 엔진 검사에는 패키지 제외나 실패 허용 목록을 두지 않습니다.

Docker 네트워크 검증에서는 같은 네트워크의 서버 이름, `host.docker.internal`의 호스트 서버, 외부 HTTPS 접근을 확인했습니다. 별도 Docker 네트워크에서도 기본 공개 포트로 ARTEX에 접속했습니다. 실제 내부망의 다른 PC·사내 서버·VPN 경로는 각 실행 환경에서 확인해야 합니다.

실제 컨테이너의 공개 인증 메타데이터 조회·로그인 URL 생성·잘못된 state 거부·승인 취소 콜백을 확인했습니다. 성공 토큰 교환은 모의 서버로 검증했으며, 실제 ChatGPT 계정 승인·추론, 계정별 Daybreak 접근과 Windows 네이티브 실행은 별도 실사용 확인 대상입니다.

GitHub 워크플로는 제거했습니다. 로컬에서 루트 `go test ./...`, Norma 폴더의 `go test ./...`, 웹의 `npm test -- --run`·`npm run check:i18n`·`npm run build:static`, 문서의 `python3 scripts/check-doc-links.py`로 검사할 수 있습니다. DB 통합 검사는 테스트 전용 `ARTEX_PG_DSN`을 지정하고 패키지별 빈 DB로 분리해 실행합니다. Compose 검사는 로컬 이미지가 준비된 뒤 `python3 scripts/test-compose.py`로 실행하며, 자체 테스트 프로젝트·볼륨을 정리합니다.
