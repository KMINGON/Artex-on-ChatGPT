# 원본 대비 변경점과 OpenAI 호환성

개인 PC에서 **ChatGPT 구독 또는 OpenAI API 키로 ARTEX를 사용하기 위한 포크**입니다. 한국어판 [artex-global의 `fdfb7a1`](https://github.com/jiwoochris/artex-global/commit/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6)을 비교 기준으로 합니다. 설치 안내는 [현재 README](../README.md)를 참고하세요.

## 기능 추가

### 로그인·모델 연결

| 기능 | 원본 | 현재 동작 |
| --- | --- | --- |
| ChatGPT 개인 계정 | 공급자 API 키 중심 | 공식 **Sign in with ChatGPT**로 계정 연결·갱신·해제. Codex 설치 없이 구독 사용 |
| Daybreak 프로그램 설정·확인 | 별도 프로그램 선택·실제 적용값 표시 없음 | API 키·구독의 요청 방식을 구분하고, 완료 응답의 실제 모델·프로그램을 연결 확인과 저장된 카드에 표시 |

기존 **OpenAI API 키 연결과 API 모델 조회**는 유지합니다. ChatGPT 계정 연결은 ARTEX 관리자 로그인과 별도이며, 구독 사용 중 API 키 과금으로 자동 전환하지 않습니다. 프로그램별 실제 요청 방식은 [Daybreak 선택](#daybreak-선택)을 참고하세요.

작업·계획·Worker, Bash 등 로컬 도구, MCP, Skills와 일반 검색 연동도 유지합니다.

### 모델 설정 화면

ChatGPT 계정 연결 카드는 유지합니다. 로그인과 모델 설정은 각각 관리하며, **모델 설정 탭의 카드 목록 아래 중앙에 있는 `＋ 모델 설정 추가`**로 모델을 등록합니다. 순환 설정 버튼은 **모델 설정 / 재시도와 백오프** 탭 오른쪽에 있습니다.

```text
ChatGPT 계정 연결 → 모델 설정 추가 → 계정 선택 → 모델 조회 → 모델 선택
OpenAI API 키    → 모델 설정 추가 → 키 입력   → 모델 조회 → 모델 선택
                                                        ↓
                                        옵션 설정 → 연결 확인 성공 → 저장
```

조회 전에는 모델 조회 버튼을 표시하고, 조회가 끝나면 모델 선택 목록과 새로고침 버튼을 표시합니다. 기존 설정을 편집할 때는 저장된 모델을 먼저 보여 주며, API 키를 다시 입력하지 않아도 저장된 키로 조회할 수 있습니다. 조회·모델 선택만으로 추론을 실행하지 않습니다. 다른 계정·키로 바꾸면 이전 목록을 재사용하지 않습니다.

새 설정은 연결된 구독 계정이 하나면 해당 계정을 미리 선택하며 API 키 방식으로 바꿀 수 있습니다. 이름은 선택한 모델에 맞춰 자동 입력하고 직접 수정할 수 있습니다. 기본 화면에서는 모델·추론 강도를 설정하고 프록시·속도 제한·컨텍스트 수동 설정·API 프로그램 등은 **고급 설정**에서 엽니다. API의 모델 ID 직접 입력도 고급 설정에 남겨 두었습니다. 구독 모델 목록에는 계정 카탈로그에 따른 **Daybreak / Standard / 미확인** 태그를 표시하며 별도 프로그램 토글은 두지 않습니다.

API는 모델 선택 목록 아래의 **Daybreak 확인** 또는 일반 **연결 확인**으로 선택한 모델의 실제 적용 프로그램을 확인합니다. 두 버튼은 현재 설정으로 같은 연결 요청을 보내므로 한 번 성공하면 충분합니다. API 프로그램의 기본값은 필드 생략이며, 지원·권한이 있는 모델에서는 OpenAI가 Daybreak를 선택합니다. 고급 설정에서 프로그램을 직접 지정했다면 그 값을 유지합니다.

성공하면 버튼에 **`실제 모델명 · Daybreak Blue / Standard · 연결됨`** 형식으로 표시하고, 응답 시간·확인 시각도 남깁니다. **현재 설정으로 연결 확인에 성공해야 저장·저장 후 사용 버튼이 활성화**됩니다. 키·계정·모델·프록시·추론 강도·API 출력 상한·프로그램을 바꾸거나 재확인에 실패하면 성공 상태를 해제합니다. 변경 전 요청이 늦게 도착해도 새 설정의 결과로 표시하지 않습니다. 편집창을 다시 열었을 때도 저장하려면 연결을 다시 확인합니다.

저장한 모델 카드에서는 API·구독 모두 실제 응답으로 확인한 **Daybreak / Standard** 태그를 사용합니다. 확인 기록이 없는 기존 프로필과 프로그램 정보가 없는 응답은 **미확인**으로 구분합니다. 기록은 확인 당시의 모델·프로그램·시각을 보관하는 표시 정보이며, 앞으로의 접근 권한이나 모든 작업의 성공을 보장하지 않습니다. 저장과 기본 모델 적용은 구분하며, 첫 사용 가능한 프로필의 자동 활성화 안내도 실제 서버 동작에 맞췄습니다.

### 한국어화

화면의 고정 라벨에 더해 **ARTEX가 기본 제공하거나 실행 중 생성하는 중국어 안내**를 한국어로 바꿨습니다.

| 범위 | 반영 내용 | 유지한 동작 |
| --- | --- | --- |
| 에이전트 | 기본 시스템 프롬프트, 변수 설명·예시, 보고서·재검증 지침, 작업·마무리 안내 | 역할, 작업 순서, 권한 범위, 템플릿 변수와 도구 호출 조건 |
| 도구 | ARTEX 도구 설명·인자 안내·오류·결과, Norma 대화형 셸·백그라운드 작업 알림 | 도구 이름·인자 키·자료형·필수값·enum·기본 인자와 실행 로직 |
| 가로채기 | 명령 규칙 20개·자산 규칙 4개의 표시 문구, Judge 정책·판정 사유, 승인·차단 안내 | 정규식·도메인·우선순위·활성 상태·시간 제한. 새 한국어 판정과 기존 중국어 판정 형식을 함께 검증 |
| 실행 화면 | 트리거 제목·컨텍스트, 첨부·인용 안내, 상태·오류·로그, 보조 질문 지침 | 기존 상태값·기록 형식. 한국어 로그 오류 분류 및 이전 인용 토큰 호환 |
| 기본 스킬 | `api-recon`, `scopesentry` 문서·예시 | 명령·프로토콜·응답 매칭 패턴과 파일 구조 |

기존 DB에는 확인된 이전 기본값과 **정확히 일치하는 부분만** 적용합니다. 도구는 설명 필드별로 비교하고, 프롬프트는 본문 전체를 비교해 새 버전을 추가합니다. 사용자 편집·도구 연결·비활성화·삭제한 규칙은 보존하며, 앞서 실행되던 기본값 강제 갱신에도 사용자 편집 보호를 추가했습니다. 새 설치는 한국어 기본값으로 시작합니다.

직접 수정한 본문, 확인되지 않은 더 오래된 기본값, 과거 대화·감사 기록·프롬프트 이력, 대상 사이트 응답과 외부 도구 출력은 일괄 번역하지 않습니다. 기존 사용자 프롬프트에 중국어 답변 지시가 남아 있다면 직접 수정하거나 에이전트 설정의 기본값 복원을 사용하세요. 도구의 기본값 복원은 연결·활성 상태도 초기화하므로 필요한 설명만 편집할 수도 있습니다.

번역 후에도 작은 컨텍스트 창에서 보조 질문 요약이 동작하도록, 실제 조립된 요청의 길이를 확인해 요약 조각 크기를 조정합니다. 스키마·템플릿·판정 파서·기존 DB 갱신은 회귀 검사로 확인합니다.

**기존 OpenAI API에서도 일반 압축은 동작했습니다.** 개선한 부분은 누락되던 OpenAI 응답 상태 보존과 공통 실행 엔진의 압축·저장 처리입니다. 메시지를 편집·압축하면 원형 상태를 그대로 재사용할 수 없어 해당 opaque 상태를 제거합니다.

프로필 적용 중 DB 확인에 실패했다면 DB 연결을 복구한 뒤 프로필을 다시 저장하거나 활성화하세요. 연결 확인 기록은 표시용이며 실행 설정·권한을 대신하지 않습니다.

원본에도 API 모델 조회가 있었습니다. 이번 변경은 조회 기능 자체를 새로 만들었다는 뜻이 아니라, **인증 방식별 조회 흐름을 맞추고 모델 목록의 부가 정보를 설정에 연결한 것**입니다. 이 포크의 이전 구독 조회에서는 OpenAI가 제공한 `available_access_programs.cyber`와 `supported_reasoning_levels`를 읽지 않아 모든 구독 모델을 미확인으로 취급했습니다. 이제 해당 정보를 전달하며, 프로그램 필드 누락과 Blue 미지원도 구분합니다. 취소는 이미 끝난 도구의 효과를 되돌리지 않습니다. 취소를 무시하는 외부 프로그램까지 모두 즉시 정지시킨다는 보장도 아닙니다. 자동 트리거는 **실행 전 대기 상태만 복구**합니다. 이미 실행을 시작한 상태에서 서버가 종료되면 결과 불명으로 남기며, 도구의 중복 실행을 피하기 위해 자동 재실행하지 않습니다. 대화 기록을 확인한 후 사용자가 재시도해야 합니다. 실행 전에 연결 미설정·로그아웃·기록된 한도 차단을 확인하면 대기 항목을 유지하고 연결 복구 후 다시 시도합니다. 원본 작업이 삭제·보관되면 미실행 항목은 취소하며 작업을 복원해도 자동으로 재발행하지 않습니다.

HTTP 200 이후에도 SSE의 `response.failed`·`error`로 요청이 실패할 수 있습니다. 오류 코드·요청 ID·단계·요청 크기를 기록하며, 출력·도구 실행 후 전체 작업을 자동 반복하지 않습니다. `Output too large` 파일 안내 자체가 모델 컨텍스트 초과를 뜻하지는 않습니다. 원본 HTTP 본문·암호화 추론·자격증명은 진단 로그에 넣지 않습니다.

## 설치·운영 개선

| 항목 | 이전 동작 | 현재 동작 |
| --- | --- | --- |
| 설치·앱 로그인 | 호스트 빌드·DB 준비·설정 토큰 입력 | Compose로 앱·웹·PostgreSQL 준비, 새 DB의 관리자 초기값 제공 |
| Docker 접속 | 루프백 게시·환경변수 프록시·컨테이너별 주소 혼동으로 접근 실패 가능 | 웹 공개 주소와 대상 접속 주소 구분, 호스트 게이트웨이 매핑, 명시한 프록시·직접 연결 적용 |
| 실행 엔진·배포 | 원본 Norma 의존성과 원본 이미지 사용 경로 | `go.mod`의 로컬 replace로 수정한 Norma를 함께 빌드하고 현재 소스로 앱 이미지 생성 |
| 브라우저·Docker | latest 패키지 설치로 구성 요소 버전과 기본 실행 경로 불일치 가능 | Chromium·Playwright 버전·경로 통일, NSS 인증서 도구와 Compose `init`·1GiB 공유 메모리 추가 |
| 검증 | 루트 Go 검사만으로 별도 Norma 모듈을 확인할 수 없음 | 루트·Norma·웹·Compose를 각각 로컬 명령으로 검사 |

- 기본 실행 경로는 **개인 PC의 Linux·WSL에서 Docker Compose로 앱과 PostgreSQL을 함께 실행**하는 방식입니다. `docker compose up -d`는 이미지가 없으면 현재 소스로 빌드하며, 소스 업데이트 후에는 `docker compose up -d --build`로 다시 빌드합니다. Go·Node.js는 이미지 빌드에서 준비합니다. 호스트 설치 방식도 유지합니다. [실행 안내](../README.md#빠른-시작)
- Compose는 웹을 `${ARTEX_BIND_IP:-0.0.0.0}:${ARTEX_PORT:-8787}`에 게시하고 DB 포트는 호스트에 열지 않습니다. `ARTEX_BIND_IP=127.0.0.1`이면 실행 PC에서만 접속합니다. 트래픽 프록시의 기본 리스너는 컨테이너 내부 `127.0.0.1:8788`입니다. Bash·로컬 도구는 컨테이너 안에서 실행되며 기존 호스트 파일·설정은 자동으로 이관하지 않습니다.
- `host.docker.internal`을 Docker 호스트 게이트웨이에 매핑합니다. 다른 컨테이너는 같은 Docker 엔진·네트워크에서 컨테이너 이름과 내부 포트로 접근합니다. 웹 공개 주소와 에이전트의 대상 주소는 별개이며, Docker 안의 `127.0.0.1`은 ARTEX 자신입니다. [접속 주소](../README.md#접속-주소)
- `.env` 없이도 실행할 수 있습니다. 관리자 초기값은 `ARTEX` / `artex1234`, 새 DB의 사용자·이름은 `artex`, 비밀번호는 `artex-local-db`, 기본 언어는 `ko`입니다. `ARTEX_ADMIN_PASSWORD`는 관리자 비밀번호가 없는 DB에만 적용됩니다. 기존 비밀번호는 `.env` 수정이나 컨테이너 재생성으로 초기화되지 않으며, 기존 PostgreSQL 볼륨의 접속 정보도 유지해야 합니다. 기본 관리자 비밀번호는 로컬 실행용입니다.

Norma는 런타임에 원본을 다운로드하지 않으며, [로컬 replace](../go.mod)가 지정하는 [`third_party/norma`](../third_party/norma/ARTEX_PATCHES.md)를 함께 빌드합니다.

소스의 `github.com/Autumn-27/artex`는 현재 프로젝트의 **Go 모듈 이름**이고, Norma도 로컬 사본으로 빌드합니다. 원본 저장소에서 실행 코드를 받아오는 경로가 아닙니다. 업데이트 다운로드는 `KMINGON/Artex-on-ChatGPT`를 사용하며, 원본 링크·저작권·라이선스 고지는 출처 기록으로 유지합니다.

## 제거·정리

### Noa·원본 잔재 정리

실험적 Noa의 설정 화면·설정 API·에이전트 연결·`noa`/`noaadapter` 패키지를 제거했습니다. 채팅·계획자·작업자·메인 에이전트는 기존 **기본 자동 압축**을 사용합니다. 오래된 도구 결과 정리, 대화 요약과 최근 메시지 보존, 문맥 초과 후 복구 및 별도의 탐색 그래프 요약은 유지합니다.

기존 DB의 `noa_compaction` 값은 더 이상 읽지 않습니다. 예전 Noa 아카이브·대화 원문을 자동 삭제하지 않으며, Noa 요약 상태는 더 이상 적용하지 않습니다. 예전 Noa 세션은 저장된 대화 이력에서 기본 압축으로 재개하므로 첫 재개에 재요약이 발생할 수 있습니다.

## API·구독 상세 동작

두 인증 방식의 모델 목록·프로그램 선택·실제 응답을 구분합니다.

### Daybreak 선택

공식 문서·API·구독 응답 확인일: **2026-10-23**. 모델과 접근 프로그램은 별도 값입니다. 모델 목록의 **선택 가능한 프로그램**, 프로필의 **요청 설정**, 연결 확인의 **실제 응답값**을 구분합니다. `-latest` 별칭이 폐지되었다고 해석하지 않으며, 기존 모델을 자동으로 다른 모델로 바꾸지 않습니다.

#### OpenAI API 키

**시스템 → LLM → 모델 설정 추가**에서 OpenAI API 키를 선택하고 키를 입력한 뒤 모델을 조회합니다. 조회 버튼이 모델 선택 목록으로 바뀌면 사용할 모델을 선택하고 **Daybreak 확인** 또는 **연결 확인**을 누릅니다. API 모델 목록은 그 키로 접근 가능한 모델 ID를 알려 주며, 모든 모델의 Responses 지원·추론 강도·Daybreak 권한까지 알려 주는 목록은 아닙니다. 조회된 모델의 기능 정보가 없으면 공식 문서 기반 옵션을 사용하고, 실제 적용 프로그램은 선택한 모델의 완료 응답으로 확인합니다. 목록 조회 단계에서 모든 모델에 추론 요청을 보내지는 않습니다. [API 모델 목록](https://developers.openai.com/api/reference/resources/models/methods/list)

새 API 설정은 프로그램을 생략해 서버의 기본 선택을 따릅니다. **Daybreak 확인**은 별도로 Blue를 강제하거나 다른 프로그램으로 재시도하는 버튼이 아닙니다. Standard 응답을 받았다고 모델·계정의 Daybreak 권한 전체가 없다고 단정하지 않으며, 네트워크·한도 오류도 Standard로 바꾸어 표시하지 않습니다. 직접 지정이 필요한 경우 **고급 설정 → API 액세스 프로그램**을 사용합니다.

| 선택 | 요청에 보내는 값 | 의미 |
| --- | --- | --- |
| 기본값 (필드 생략) | 필드 생략 | 모델·조직·프로젝트 권한에 따라 서버가 결정. **Daybreak 끄기와 다름** |
| `standard` (Standard) | `access_programs.cyber=standard` | 지원 모델에서 표준 보호 설정 명시 |
| `daybreak_blue` (Daybreak Blue) | `access_programs.cyber=daybreak_blue` | 해당 모델·프로젝트의 승인 필요 |
| `daybreak_red` (Daybreak Red) | `access_programs.cyber=daybreak_red` | 해당 cyber 모델과 별도 Red 승인 필요 |

`gpt-6-sol`의 Daybreak 값은 Blue입니다. `gpt-6.1-sol`·`gpt-6-astra`도 요청값은 Blue지만 조직의 **Red 승인과 프로젝트 접근 설정**이 필요하며, Red 값을 보내면 안 됩니다. `gpt-5.6-cyber`는 Red를 사용합니다. 프로그램 지정만으로 권한이 생기지 않습니다. [공식 Daybreak 안내](https://developers.openai.com/api/docs/guides/daybreak)

API의 모델별 지원 조합과 사용 권한은 OpenAI가 검증하고, 오류를 그대로 알립니다. ARTEX의 정적인 문서 정보가 더 최신인 계정 응답을 막지 않도록 백엔드는 프로그램 값의 형식과 구독의 명시 Blue·Red 제한을 검사합니다. 화면에서도 문서 목록에 없는 기존 값은 안내와 함께 유지하고 연결 확인을 허용합니다. 반면 계정 모델 목록이 명시한 지원값과 맞지 않는 설정은 직접 수정하도록 안내합니다. ARTEX가 다른 모델·프로그램·과금 방식으로 바꾸어 성공처럼 처리하지 않습니다. 연결 테스트에는 서버가 반환한 실제 모델과 접근 프로그램을 표시하며, 사용량 기록에도 해당 메타데이터를 보존합니다. 공식 응답의 `access_programs: null`은 Standard로 해석하지만 필드 자체가 누락되면 미확인으로 둡니다. [Responses API 요청 규약](https://developers.openai.com/api/reference/resources/responses/methods/create)

#### ChatGPT 구독

**연결한 계정의 모델을 조회하고 그 목록에서 선택**합니다. 계정 전체나 모델 이름으로 Daybreak 여부를 추정하지 않고, 해당 계정·모델의 `available_access_programs.cyber`로 화면을 구성합니다. `supported_reasoning_levels`는 추론 강도 선택지에 반영하고, `default_reasoning_level`은 기본값 안내에 표시합니다. 기본값 선택 시 요청에는 추론 강도를 보내지 않으며, 계정의 기본값을 사용자가 지정한 값처럼 저장하지 않습니다. 다른 계정이나 API 키의 목록은 구독 계정의 권한으로 사용하지 않습니다. [구독 모델·추론 안내](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

| 계정·모델이 제공한 프로그램 | 모델 목록의 태그 | 새 설정의 실제 요청 |
| --- | --- | --- |
| `standard`, `daybreak_blue` | **Daybreak** | `access_programs` 생략 |
| `standard`만 제공 | **Standard** | `cyber: "standard"` |
| `daybreak_blue`만 제공 | **Daybreak** | `access_programs` 생략 |
| 조회 전 또는 프로그램 정보 누락 | **미확인** | `access_programs` 생략 |

목록의 **Daybreak 태그는 계정 카탈로그의 지원 정보**이고, 연결 후 표시하는 프로그램은 **실제 완료 응답**입니다. 둘이 다르면 실제 응답을 우선 표시하고 차이를 안내합니다. 프로그램 생략은 서버의 선택을 따르므로, 조회에서 Daybreak를 지원한다고 확인한 것만으로 매 호출의 적용값까지 확정하지 않습니다.

기존에 Standard를 명시한 구독 설정은 모델·계정 변경만으로 자동 선택으로 바꾸지 않습니다. 해당 모델에서 자동 선택이 가능하면 기존 Standard 유지 안내와 **자동 선택으로 변경** 버튼을 표시합니다. 사용자가 전환하면 다시 연결을 확인한 뒤 저장합니다. 기존 빈값은 지원 정보가 Standard만 제공하는 것으로 확인되면 Standard로 맞춥니다. API도 모델을 바꿔도 사용자가 명시한 프로그램 선택을 유지하며, 새 모델과의 호환성은 연결 확인으로 검증합니다.

현재 SIWC 경로는 **생략 또는 명시적 Standard**를 지원하도록 구성했습니다. 구독에서 Blue·Red를 명시하는 설정은 허용하지 않습니다. 개발 과정의 실제 구독 계정 시험에서 GPT-6 Sol은 프로그램 생략 시 Blue, Standard 명시 시 Standard를 반환했으나, Blue 명시 시에는 Standard를 반환했습니다. Astra·6.1 Sol은 같은 계정에서 Standard만 조회되었고 Blue 명시 요청은 거부되었습니다. 이 관측은 해당 계정·시점의 SIWC 호출 결과이며, 일반 API 키 경로의 결함이나 모든 계정의 동작으로 해석하지 않습니다.

Codex에도 별도의 [Daybreak 선택 기능](https://help.openai.com/en/articles/20001607-using-daybreak-in-codex-cli)이 있습니다. ARTEX는 Codex를 실행하거나 내부 호출 주소로 우회하지 않고, 공식 SIWC의 공개 Responses 경로를 계속 사용합니다. 반환 프로그램이 요청 의도와 다르면 실제 응답값을 표시하며, 다른 모델·인증 방식으로 몰래 바꾸지 않습니다.

### API와 구독의 차이

| 항목 | OpenAI API 키 | ChatGPT 구독 |
| --- | --- | --- |
| 사용량·과금 | API 프로젝트의 과금·한도 | 연결한 ChatGPT 계정의 요금제·앱 사용 한도 |
| `temperature` | 내부 호출에서 지원 조건에 맞는 경우 전달. Judge는 강제값 제거 | 전송하지 않음 |
| `max_output_tokens` | 서버 출력 상한 전달 | 전송하지 않음. 보조 요청에 간결한 출력 지시·로컬 시간/수신량 제한 적용 |
| 모델 조회 | 입력한 키 또는 저장된 키로 조회. 기능·프로그램 권한은 목록에 없는 경우가 있음 | 선택한 계정의 모델·프로그램·추론 옵션을 함께 조회 |
| 추론 강도 | 모델 목록의 기능 정보 또는 공식 문서 기반 선택지. 실제 지원은 OpenAI가 검증 | 계정 모델의 지원값으로 선택지 구성하고 기본 추론 강도 안내. 기본값 생략과 `none`은 서로 다름 |
| Daybreak | 기본값은 서버 선택. 선택한 모델의 실제 연결로 확인하며 고급 설정에서 프로그램 명시 가능 | Blue가 제공된 모델에 **Daybreak** 태그, 요청은 필드 생략. Standard만 제공하는 모델은 명시 전송 |
| 연결·저장 | 실제 모델·프로그램을 확인한 뒤 저장. 카드에 마지막 확인 결과 표시 | 동일. 목록의 지원 태그와 실제 응답이 다르면 안내 |
| 도구·입력 | 텍스트·로컬 function·MCP, 도구 결과와 `Read`의 이미지 | 동일한 이미지 변환 사용. 채팅 이미지 업로더·OpenAI 호스팅 도구는 미구현 |
| 응답 상태 | reasoning·`phase`·항목 순서를 완료 응답에서 보존 | 동일한 어댑터·저장 형식 |
| 실패·전환 | 명시적으로 설정한 API 프로필 전환 정책 유지. 원형 상태가 있으면 다른 연결로 자동 재전송 차단 | 유료 API 키 경로로 자동 전환하지 않음 |

구독의 로컬 제한은 서버의 생성 토큰·추론 비용 상한을 대체하지 않습니다. 도구가 없고 호출자가 추론 비활성화와 출력 토큰 수를 요청하는 보조 호출에만 90초와 8–64KiB 수신 제한을 적용합니다. 무작위성 제어나 추론 완전 비활성화를 복원하는 기능이 아닙니다. [SIWC 미리보기 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

한도 오류 후에는 ChatGPT Usage 설정을 확인하고 ARTEX의 **한도 재확인**을 사용합니다. 한 번의 실제 추론을 허용하는 검사로 사용량이 발생할 수 있으며, 성공해야 신규 요청을 다시 허용합니다. 재시작·토큰 갱신만으로 한도가 풀렸다고 간주하지 않고, 계정의 전체 잔량이나 리셋 시간을 추정하지 않습니다. [오류·복구 안내](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)

## 업데이트·데이터 보존

- 업데이트 전 앱을 종료하고 DB·앱 파일·인증 저장소를 백업하세요. Compose는 `pgdata`(DB), `artex-data`(`/app/data`), `artex-auth`(`/app/auth`)를 보존합니다. `docker compose stop` 뒤 `up -d`로 재실행하며, `down`은 볼륨을 보존하지만 **`down -v`는 세 볼륨의 데이터를 삭제**합니다. 같은 Compose 프로젝트의 기존 `pgdata`는 유지하고, 다른 호스트 DB·`data/`·인증 폴더는 자동 이관하지 않습니다.
- 앱 시작 시 프로필의 접근 프로그램·연결 확인 기록, 사용량 수신 여부, 트리거 대기/timeout 기록을 DB에 추가합니다. 연결 확인 기록이 없는 기존 프로필은 미확인으로 표시하며 설정·작업·대화는 삭제하지 않습니다. 확인 기록은 실행 권한을 대신하지 않습니다.
- 새 체크포인트는 완성된 묶음만 읽습니다. 알려진 미완성 묶음은 원본 JSONL을 보존하고 `.recovered` 파생 파일로 재개합니다. 마지막 정상 체크포인트 뒤에 저장된 실제 메시지도 보존합니다. 일반 손상이나 알 수 없는 형식은 임의 복구하지 않고 중지합니다. 기록 동기화로 디스크 I/O는 늘어나며, 원격 모델의 응답 속도가 빨라지는 변경은 아닙니다.
- 옛 체크포인트에는 완료 메타데이터가 없어 일부 저장인지 확정할 수 없는 경우가 있습니다. 새 형식으로 실행한 세션을 구버전 바이너리로 계속 쓰거나 두 버전으로 동시에 쓰지 마세요. 롤백은 백업한 DB·파일과 대응하는 버전을 함께 사용해야 합니다. [Norma 저장 형식 변경](../third_party/norma/ARTEX_PATCHES.md)
- 계정·API 키·모델·**명시적 접근 프로그램**의 변경을 관측하면 새 컨텍스트를 시작합니다. 이전 파일·작업은 보존하지만 모델의 대화 기억은 이어지지 않습니다. 프로그램을 설정하지 않은 기존 프로필의 연결 ID는 유지합니다. 별칭 뒤의 서버 모델 변경까지 로컬 설정만으로 미리 알아내지는 못합니다.
- OAuth 자격증명은 PostgreSQL이나 브라우저에 저장하지 않습니다. Compose에서는 `XDG_CONFIG_HOME=/app/auth` 아래 `/app/auth/artex-on-chatgpt/`를 사용하며 관리자 세션 서명 키도 `artex-auth` 볼륨에 보관합니다. 호스트 설치의 기본 경로는 `~/.config/artex-on-chatgpt/`입니다. OAuth 저장소 권한은 폴더 `0700`·파일 `0600`입니다. 연결 해제와 서버 재시작은 다른 동작입니다.
- Compose의 OAuth 콜백은 별도 임시 포트 대신 공유 웹 포트의 `http://127.0.0.1:${ARTEX_PORT}/auth/callback`을 사용합니다. 브라우저는 Docker를 실행한 같은 PC에서 사용합니다. 관리자 로그인 뒤의 ChatGPT 계정 연결·모델 프로필 저장·활성화 절차는 그대로입니다.
- 브라우저 프로필은 `artex-auth`에 저장합니다. 작업 프리셋의 정책·버전과 Worker 수는 DB에 저장하며 기존 작업에 새 프리셋을 강제로 적용하지 않습니다. 일반 설정의 자원 프리셋도 명시적으로 선택할 때 적용합니다.
- OpenAI 서버 압축과 모델 자동 업그레이드는 이번 범위에 포함하지 않습니다. 이미지 입력은 MCP와 `Read` 경로에서 지원합니다.

## 검증 범위

자동 회귀 검사는 모의 OpenAI SSE, 실제 로컬 파일·프로세스와 격리 PostgreSQL을 사용합니다. 실제 API 키·ChatGPT 계정·운영 DB는 사용하지 않습니다. 계정별 프로그램 응답 확인은 자동 검사와 분리해 허용된 API 키·구독 계정의 짧은 연결 요청으로 진행합니다.

2026-10-22 모델 설정 변경 후 루트 Go 전체 검사, 웹 **42개 테스트**(LLM 설정 **21개**), TypeScript 검사와 Docker 이미지 빌드·앱 정상 기동을 확인했습니다. 2026-10-23에는 실제 API 키의 모델 **139개**, 구독 계정의 표시용 모델 **8개**를 조회했습니다. API 응답에는 프로그램·추론 강도 정보가 없었고, 구독 응답의 프로그램·추론 강도·기본 추론 강도·정보 출처는 ARTEX 조회 결과에 보존되었습니다.

위 결과는 모두 `response.completed`까지 확인했습니다. Blue 명시 비교는 ARTEX를 거치지 않고 같은 공개 Responses 주소·요청 본문에 인증 방식만 바꾸어도 재현되었습니다. 해당 SIWC 응답의 차이가 프로그램 적용 자체인지 응답 메타데이터 문제인지는 공개 응답만으로 확정하지 않습니다. 이 API 키에서 Astra·6.1 Sol의 Blue 요청은 `unsupported_access_program`으로 거절되었습니다.

2026-10-23의 실제 Chromium 확인에서는 API 모델 조회·Blue/Standard 연결·저장·저장된 키 재조회, 구독 연결·설정 변경에 따른 이전 결과 해제를 확인했고 JavaScript 오류는 없었습니다. 이 실행은 이번 연결 필수·태그 중심 화면으로 변경하기 전 버전을 대상으로 했습니다. API·구독 GPT-6 Sol과 API `gpt-4o-mini`에서는 실제 어댑터의 함수 호출 → 도구 결과 전달 → 최종 답변까지 확인했습니다. 짧은 요청에 암호화 추론 항목은 생성되지 않아 해당 항목의 보존은 모의 회귀 검사 범위로 남습니다.

연결 필수·태그 중심 화면 변경에서는 웹 **57개 테스트**(LLM 설정 **36개**)와 정적 빌드를 통과했습니다. 연결 전 저장 차단, 설정 변경·재확인 실패·지연 응답 처리, 구독의 기존 Standard 보존, 실제 응답 프로그램의 표시·저장을 검사합니다. Go 패키지 검사도 통과했으며, 공유 DB 병렬 실행에서 잠금·임시 파일 정리 충돌이 발생한 DB·서버 패키지는 각각 빈 DB에서 분리 실행했습니다. 실제 PostgreSQL에서 연결 기록 저장·재조회·제거를 확인했고, 외부 전용 설정이 필요한 `TestLiveContextReview` 1건은 SKIP입니다. 이 변경에 대한 OpenAI 실계정 호출과 실제 브라우저 재검증은 별도로 수행하지 않았습니다.

루트 Go **19개 패키지**를 패키지별 빈 PostgreSQL DB에서 검사하고, Docker 소스 빌드와 [Compose 검사](../scripts/test-compose.py)를 통과했습니다. 앱 초기화·관리자 로그인·한국어 기본값·인증 경계·재생성 후 데이터 보존을 확인했습니다. Noa 패키지와 해당 전용 검사는 제거했으며, 현재 엔진 검사에는 패키지 제외나 실패 허용 목록을 두지 않습니다.

Docker 네트워크 검증에서는 같은 네트워크의 서버 이름, `host.docker.internal`의 호스트 서버, 외부 HTTPS 접근을 확인했습니다. 별도 Docker 네트워크에서도 기본 공개 포트로 ARTEX에 접속했습니다. 실제 내부망의 다른 PC·사내 서버·VPN 경로는 각 실행 환경에서 확인해야 합니다.
